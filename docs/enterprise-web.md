# 企业经营工作台

E6.1 新建浏览器入口 `apps/web` 与共享界面包 `packages/product-ui`。本工作包仍在实施和验证中，源码或页面存在不代表工程验收、真实身份联调或试点已经通过。范围依据为[完整执行计划](proposals/enterprise-operating-platform-2026-11-02.md)第 2.3、2.4 和 9 节。

## 界面与业务边界

主导航固定为经营总览、待我处理、客户与销售、项目与交付、资金与复盘、知识与成果。管理区独立包含组织与权限、Agent 与流程、连接与模型、用量与审计。Coding 不进入经营首次使用流程。

列表、详情和资料使用当前 Host 返回的有权数据。缺失金额不补零，界面不从关联记录推算余额、毛利或客户验收状态。订单资金、项目进度与成本使用对应服务端查询。没有数据、没有权限、服务不可用和暂未接入分别显示。

E2 业务页面可以办理明确的业务批准和事实确认。界面展示当前内容、原始版本和核对说明，由人员逐次提交。集中人工待办、Agent 计划与授权差异、执行批准和未知动作核对属于 E6.2；不能用候选内容或占位响应显示已批准、已到账或已验收。

## 同源入口

构建使用 Node.js 22.19.x、npm 11.10.1 和仓库固定的 TypeScript 5.7.2。安装现有锁文件后，从工作树根目录依次构建：

```bash
npm run build -w @mn/contracts
npm run build -w @mn/product-ui
npm run build -w @mn/web
```

产物位于 `apps/web/dist`，不提交到 Git。由 Host 同源服务 `/` 和 `/assets/*`；页面使用 hash 导航，不要求任意路径回退到 HTML。应用不嵌入外部脚本、样式或远程字体，不在浏览器保存模型密钥或 OIDC 令牌。

在既有[企业身份配置](enterprise-identity.md)中，通过绝对路径 `webRoot` 指定该产物目录。`loginOrganizations` 是管理员明确批准公开显示的企业登录目录，每项包含已有提供方的 `id` 和展示名称 `name`。目录不从数据库自动生成；未配置时为空。不要把凭据写入这些字段或提交配置文件。

登录经 `/v2/auth/login` 跳转至已配置的企业身份服务，回调仍执行 state、nonce、PKCE 和单次凭据检查。前端仅使用 HttpOnly Cookie 会话。公开目录为空时，页面应提示使用管理员提供的企业登录入口，不要求经营人员填写技术组织标识。

企业及初始管理员仍由受信运维配置开通，没有公开自助创建企业接口。已登录管理员可建立经营主体并配置业务权限；管理员身份不自动获得销售、项目或财务权限。

## 契约与状态处理

共享界面只依赖 contracts、React 和仓库已有 UI 依赖。请求和响应使用 `@mn/contracts/enterprise-client`，从同一 API schema 校验。浏览器安全入口不引入 Kernel、Storage、私有企业服务或服务端摘要实现。

| 边界 | 界面处理 |
| --- | --- |
| 会话 | 每次读取禁止缓存；会话失效后清空页面身份和资料 |
| 写入 | 使用当前 CSRF token；同一待核对请求保留原输入和幂等键，不自动生成新请求重试 |
| 工作区切换 | 立即移除上一工作区的数据；中止旧读取，忽略迟到的成功和错误响应 |
| 业务字段 | 能力查询返回当前可读写字段上限，实际展示还须以响应中存在的字段为准 |
| 业务表单 | 操作菜单逐项列入白名单；schema 只驱动受控字段与结构校验，不提供 JSON 命令编辑器 |
| 引用与版本 | 从有权业务记录选择器取得原始引用；ID、版本、摘要不作为普通表单输入 |
| 业务预检 | 完整命令先经 `checkEnterpriseBusinessCommand`；正式写入继续由 Host 重验权限、原版本和领域规则 |
| 客户归属 | 用真实拟建客户 ID 和已填写名称查询可选部门；候选仅说明当前允许的归属范围 |
| 业务批准 | 字段权限不等于能够批准；制单与批准分离、关联资料和有效期均由 Host 判断 |
| 资料 | 文件关联真实业务来源和字段，正文按普通文本呈现；读取与导出重新检查权限 |

业务页面修改联系人时必须能核对完整待替换字段。不能因为响应中没有电子邮箱或电话，就把被隐藏的内容当作空值覆盖。

`queryEnterpriseCustomerCreationDepartments` 使用 `POST /v2/workspaces/{workspaceId}/customer-creation-departments/queries`，请求仅包含 `{ type: 'customer.create', id, name }`，返回 `departments: [{ id, name }]` 和 `allowUnassigned`。它是需要当前会话与 CSRF 的只读查询，不要求幂等键，不创建客户、批准或事件。Host 在一致性快照中复用同一客户创建判断，只返回当前有权选择的部门；未指定部门也单独检查。无权部门、其他企业部门和成员目录不会随响应返回。

前端必须使用该客户真实拟建 ID 和当前已填写名称，不能以虚构名称或探针 ID 查询。输入变化后重新查询并清除失效选择；`allowUnassigned` 为 `false` 时，必须从当前候选中选择部门。归属候选不保证完整创建命令一定成功，已占用 ID、权限撤销和授权到期都可能使候选失效；提交前仍须完整预检，写入时再次校验。加载期间撤权或投影后授权到期会触发一致性复验，未知异常返回失败，不伪装成成功或空候选。

对象能力中的 `people` 只提供该对象已获准显示的人员引用与姓名映射，每项仅含 `principalId` 和 `displayName`。固定来源为归属人、制单人，以及对象明确记录的目标负责人、交付接收人、客户确认人、商业制单人和项目确认人；按对象类型限制，不递归扫描正文或追查批准引用。未知成员省略，不能借该数组枚举其他人员、读取身份主体或替代管理员成员目录。历史引用可以显示已停用成员的既有姓名，但姓名可见不表示有当前业务或批准权限，归属人也不替代实际制单人。

能力查询通过 Host 专用的一致性只读入口，在原生事务提交点重新核对事件版本和可见投影。加载期间撤权或计算后字段授权到期时，会拒绝或重新读取，最多重试八轮；缺少该读取能力或提交检查点时失败关闭。该检查不保留后续批准权，正式命令仍须重新校验。

品牌图片来自 `assets/brand/muniu-logo.png`，浏览器副本位于 `apps/web/src/assets/muniu-logo.png`。保留原始内容和比例，由 Shell 注入共享界面，不重绘或改变颜色。

## 合成浏览器验收夹具

本地浏览器验收使用 `scripts/lib/enterprise-web-fixture.mjs` 导出的 `startEnterpriseWebFixture()`，或其 CLI。夹具启动真实企业 Host，复用 E1 的合成 OIDC 发行方和真实授权码、PKCE、签名及回调处理；页面通过 HttpOnly 会话访问业务，不粘贴 Bearer 或绕过登录。它不代表真实企业身份发行方联调已经完成。

先按[开发指南](development.md)构建 Host 及其依赖，并完成 Web 构建，再生成共享测试发行方的产物并启动：

```bash
node node_modules/typescript/bin/tsc -p apps/host/tsconfig.test.json
node scripts/enterprise-web-fixture.mjs --web-root /absolute/path/to/muniu/apps/web/dist --mode seeded
```

CLI 仅输出 `status`、`synthetic`、`mode` 和回环地址 `origin`，不输出 Cookie、密钥或邀请令牌。在独立测试浏览器上下文中打开该地址，选择合成企业，再在合成发行方页面选择账号，避免与已有本地服务共用浏览器会话。账号选择页只接受固定账号和已登记的回调地址。

| 模式 | 初始状态及用途 |
| --- | --- |
| `seeded`，默认 | 通过真实业务命令创建客户、联系人、商机、服务、待批准报价、生效订单、项目、付款期、部分到账及文本资料；用于列表、详情、业务写入、资料与字段隔离验收 |
| `empty` | 已有工作区和显式业务授权，但没有业务种子；用于空状态和首条业务记录 |
| `uninitialized` | 只开通合成企业和账号，没有工作区或业务授权；由纯组织管理员在页面完成初始化与授权 |

| 合成账号 | 用途 |
| --- | --- |
| 组织管理员 `admin` | 只具有组织管理权限，不自动获得业务读取或批准权 |
| 销售 `sales` | 创建本人客户、商机和报价；具备种子所需的价格与联系方式权限 |
| 经理 `manager` | 独立批准销售制作的报价；另有明确授予的测试项目与财务权限，用于种子的交付和独立资金批准 |
| 财务 `finance` | 制作付款期与到账记录；种子由另一名具备财务权限的账号确认 |
| 项目制单人 `project-maker` | 项目与交付制单、商务价格核对；商务批准由独立经理办理 |
| 只读成员 `reader` | 只读公共业务字段，不读取价格、成本或联系方式 |
| 待邀请成员 `invitee` | 不预先加入企业；邀请前登录被拒绝，管理员邀请后可按真实流程登录并接受邀请 |

每次启动使用新建临时目录、独立 SQLite/FileCAS、内存合成密钥和真实当前时钟，不读取用户状态或真实凭据。后台执行循环关闭，不调用模型或真实外部业务服务。退出时按 Ctrl+C 或发送 SIGTERM，夹具关闭自己的监听并删除自己的临时状态，保留传入的 Web 构建目录。

工厂返回 `origin`、`close()`、合成账号与初始业务引用。受控钩子只允许改变固定合成客户的版本、撤销指定合成账号的授权、停用该账号以及读取登录协议计数；不提供浏览器可调用的测试后门。版本钩子使用真实业务命令，撤权使用真实企业权限服务，不能用修改页面数据代替服务端事实。

轻量生命周期与登录协议测试入口为：

```bash
node --test --test-concurrency=1 scripts/test/enterprise-web-fixture.test.mjs
```

这些测试覆盖单次登录、错误 PKCE、回调与账号限制、邀请、字段隔离、版本冲突和退出清理。真实页面交互由单独的浏览器验收连接该夹具，不能仅凭夹具就绪或协议测试通过记为界面验收通过。

## 验证

共享界面基础测试入口为：

```bash
npm run test -w @mn/product-ui
```

测试覆盖同源会话、CSRF、原输入与幂等键、跨会话旧请求、工作区切换、撤权清空、六导航、字段隔离及受控业务表单。浏览器验收另须连接真实 Host 与隔离合成身份服务，检查登录、初始化、业务写入、权限变化和静态资源策略。结构或构建通过不能代替浏览器行为通过；合成身份通过不能计为真实企业 OIDC 联调通过。

完整浏览器入口为 `npm run verify:web-ui`。该命令构建依赖、运行共享 UI 单元测试，再串行执行 12 个独立浏览器场景；每个场景使用自己的 Host、身份服务、数据库和浏览器，完成后清理。需要与锁定 `playwright-core` 匹配的 Chromium；缺少浏览器时检查失败，不返回占位成功。

完成 `npm ci` 后，用 `node node_modules/playwright-core/cli.js install chromium` 安装锁定依赖对应的浏览器。Linux 验收机器若缺系统库，使用同一命令并加 `--with-deps`，由该独立验收机器的管理员安装依赖。脚本通过 `chromium.launch()` 查找 Playwright 默认缓存，不调用日常 Chrome 配置；可用标准 `PLAYWRIGHT_BROWSERS_PATH` 指定独立缓存目录，安装与执行时须保持一致。

当前浏览器套件已实际覆盖 43 种业务命令，包括独立批准、部分交付与验收、付款期修订、收退款、四种金额调整、费用完整性和复盘。候选部门、邀请接受、撤权、迟到响应、文件读取中止及未知结果原请求核对另有场景。逐项证据与剩余检查见[界面验收清单](enterprise-acceptance/enterprise-web-qa-2026-11-05.json)。本包的完整工程出口仍在验证中。
