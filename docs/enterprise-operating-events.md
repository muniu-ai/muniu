# 企业来源事件与持续规则

E4.1 接入明确请求、内置业务事件和持久定时事件，并提供 Sales、企业微信适配器使用的受信接收端口。接收与评估使用 E1 身份、当前对象及字段权限、E3 共享预算和现有 Worker。Sales 与企业微信的真实连接分别由 E5.2、E5.3 验收。

本包形成有来源、有费用记录的工作候选。观察模式不会创建 Goal；执行模式的候选由[动态计划与监督](enterprise-agent-coordination.md)校验计划与工作授权。规则名称、订阅和模型建议均不授予权限。

## 接收、游标和定时

稳定去重键由企业、来源实例、来源事件 ID 和类型组成。同一个来源事件不能用不同内容重发；游标、事件和待评估批次在同一事务保存。版本冲突或最终授权检查失败时全部回滚。无法识别的发送者只进入隔离记录，自身通知被过滤。不同对象不会仅因标题相近合并。

同一规则版本、来源和明确对象集合形成一个主题。评估过程中到来的同主题事件合并到下一批，不改变正在评估的输入。订阅只把后续事件关联到原批次；投递及读取仍检查当前权限，不能从订阅继承资料权限。

新工作区建立独立的 `builtin:<workspaceId>` 和 `timer:<workspaceId>` 来源。内置游标从初始化时的当前业务事实位置开始，随后接收新事实，不回放此前历史。重启保留原游标。Sales 适配端口固定五分钟轮询，失败保留游标并指数退避，最长一小时；持久认领版本阻止过期轮询结果提交。

定时检查按分钟执行，规则可以配置更长周期。周期键和业务版本摘要持久保存；同周期多副本只触发一次，业务版本没有变化时只推进检查点，不创建评估。

## 规则与责任

管理员定义来源、事件类型、明确对象和字段、模式、有效期、单次评估上限及通知要求。负责人必须明确接受；管理员不能代替另一人接受责任。规则的有效权限始终是负责人当前权限与规则范围的交集。

规则保存接受时的身份代次、权限依据和对象关联。负责人停用、撤权、规则到期或关联范围改变后停止新增派发；来源接收及分钟检查将失效规则标为暂停。撤销角色后重新授予相同角色，不会复活旧接受记录。接任或范围调整需要新规则版本及新的明确接受。

人工请求单独接收并优先派发。取消和人员审批通过 Host 直接处理，不等待普通模型评估完成。租户派发轮次持久保存；多个调度器竞争同一轮次时，只有一个能认领。局部模型工作默认串行执行，不增设独立任务引擎。

## 持久评估与费用

管理员未配置模型、额度或当前责任权限时，事件保留为未评估，并显示缺项。每次入站模型评估先创建 `EvaluationAttempt`、原生执行授权、预算预留和 Job，再由 Worker 保存受保护模型请求、提交计量承诺并调用模型。输入仅包含获准字段和对应来源，模型没有工具能力。

评估预算同时受工作区累计总额、按 UTC 日期计算的入站评估日额度和单次上限约束。它与 E3 的动作预算共享工作区账户；增加事件、修改配额或更换规则不能清零已有用量和预留。观察模式和未接单候选也计费。精确模型费用以十亿分之一分记录；共享整数额度按每次评估向上取整到分，额度占用不能当作供应商账单费用。

候选必须使用允许的结构，且引用本批次的来源事件。模型输出不能自行创建业务事实、扩大权限或批准动作。结果读取再次检查当前字段权限；模型凭据不会进入结果接口。

模型已提交请求但响应或费用不明时，原评估和预留保持待核对。重启、租约接管或投影重建均不能再次发送该请求。尚未派发的批次取消后不再创建 Job；已排队但未提交模型请求的 Job 在领取时结束并释放预留，重启也不会调用模型。在途评估保存取消意图并尽力中断；费用未知时仍显示待核对，已知费用结算后显示已取消。已完成或已阻断批次拒绝再次取消，可通过批次状态和评估结果确认当前结果。

当前没有通用供应商账单核对接口，不能通过手填零费用释放未知预留。已知用量仍按真实计量结算，不能因为取消或撤权而抹去已发生费用。

## 入口与配置

`npm run dev:enterprise` 在独立企业状态目录启动接收和评估循环，每五秒检查一次；内部定时仍以持久分钟键为准。缺少模型时只管理业务及保存未评估事件。程序化 `startEnterpriseLocalHost` 默认不启动后台循环，可通过 `operatingBackground: true` 启用，或调用 `runOperatingCycle()` 执行一轮。关闭入口会停止循环并中断本实例的在途评估。

企业配置文件由 `MN_ENTERPRISE_CONFIG_FILE` 指定。可选 `evaluationModels` 按企业、工作区登记模型绑定，入站评估使用首个绑定，每项包含：

| 字段 | 含义 |
| --- | --- |
| `tenantId`、`workspaceId` | 已创建的企业和工作区标识 |
| `id`、`version` | 模型绑定标识及正整数版本 |
| `providerId`、`modelId` | 现有 BYOK 提供方和模型标识 |
| `secretEnvironment` | 以 `MN_ENTERPRISE_MODEL_` 开头的环境变量名，仅保存名称 |

完成模型绑定后，还需按[企业额度配置](enterprise-access.md#额度配置)设置 E1 上限：平台运维先通过配置文件的 `platformQuotas` 登记租户额度，管理员再向 `/v2/workspaces/{workspaceId}/quota` 提交工作区额度。`tokens`、`costMinorUnits` 是总额，`evaluationDailyTokens`、`evaluationDailyCostMinorUnits` 是日额度，`singleEvaluationTokens`、`singleEvaluationCostMinorUnits` 是单次上限；同时填写有效期与非零并发上限。工作区上限不得超过平台上限，规则的单次评估预算不得超过工作区单次上限。最后由负责人明确接受规则。未配置有效额度时仍不调用模型。

托管评估当前只使用已有人民币计价记录的模型；缺少价格或币种不符时保留未评估，不读取凭据，也不请求模型预检。它不会猜测汇率或按零费用调用未计价模型。新入口不读取旧模型凭据。测试用合成模型只能由受信测试装配注入，不能在配置文件中冒充真实模型结果。

## HTTP 接口

接口从[企业 OpenAPI](reference/enterprise-openapi.yaml)生成。写入要求企业会话、同源、CSRF 和 `Idempotency-Key`；已有对象控制同时要求 `expectedStreamVersion`。

| 路径 | 行为 |
| --- | --- |
| `/v2/workspaces/{workspaceId}/operating-state` | GET 当前可见来源、规则及最近接收批次；每类最多 100 项，更多记录以 `hasMore` 明示 |
| `/v2/workspaces/{workspaceId}/operating-policies` | POST 管理员创建或修订规则 |
| `/v2/workspaces/{workspaceId}/operating-policies/{policyId}/commands` | POST 负责人接受，或负责人、管理员暂停及关闭 |
| `/v2/workspaces/{workspaceId}/operating-requests` | POST 人员明确提出有对象范围的请求 |
| `/v2/workspaces/{workspaceId}/operating-batches/{batchId}/cancellations` | POST 保存取消意图，未知费用继续保留 |
| `/v2/workspaces/{workspaceId}/operating-batches/{batchId}/subscriptions` | POST 原责任人订阅明确对象的后续事件 |
| `/v2/workspaces/{workspaceId}/operating-batches/{batchId}/updates` | GET 按当前资料权限读取订阅事件标识 |
| `/v2/evaluations/{attemptId}` | GET 原责任人按当前资料权限读取候选及计量状态 |

状态列表当前不支持翻页；`hasMore` 只说明存在更早记录，不能据此调用尚未实现的历史列表接口。持有评估标识时仍可按标识读取有权查看的结果。完整历史列表由后继界面工作包补齐。

来源登记和批量接收不是公共 HTTP 入口。Host 只向已经认证、固定企业及来源实例的适配器提供端口；外部厂商不需要添加木牛的业务请求头。

## 验证

`npm run verify:enterprise-operating` 检查来源、规则、权限、计量、订阅、HTTP 和本地入口。`npm run verify:enterprise-operating-postgres` 使用隔离 PostgreSQL、合成 HTTP 模型及真实子进程，复验 E3 故障协议和 E4 入站评估。

验收结果见[E4.1 验收记录](verification/enterprise-e4-1-2026-11-04.md)。真实模型质量、Sales 与企业微信联调、容量和试点不由合成测试替代。
