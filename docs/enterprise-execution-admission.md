# 企业执行准入

E3.2 将企业身份、业务对象和字段权限接入[持久动作](enterprise-actions.md)。内置业务管理继续使用[企业登录](enterprise-identity.md)与[客户到订单](enterprise-sales-chain.md)接口；执行服务不会因为成员是管理员、Agent 名称包含某种岗位，或策略已经创建，就自动授予业务权限。

## 当前授权

执行范围固定责任人及其身份代次、职责版本、对象版本、可读字段、提供方绑定、输入摘要、期限和预算。身份与权限来自 E1 的认证事件；Kernel 中的运行身份只服务于现有执行机制，不能代替业务权限。

准备、排队、提交工具承诺及恢复时，检查人员当前权限、职责能力、提供方能力、执行授权和租户配额的交集。角色撤销后再以新记录授予相同角色，不会复活旧执行或旧策略。已有动作需要重新准备或按其真实回执核对。

存储先完成异步加密准备，再执行只读、同步的提交检查。检查失败会回滚事件、投影、Job 与幂等记录；Promise、布尔返回值、检查期间的写入及事务结束后的旧句柄均拒绝。PostgreSQL 保留既有异步事务回调能力，提交检查本身仍必须同步。

新企业初始化事实确认之后，业务事件和通用执行事件可以共用同一认证事件历史。这个入口仍拒绝以旧状态初始化新企业，也不读取旧状态目录。运行身份、授权范围、预算及幂等映射均使用受保护事实存储。

## 业务批准和执行批准

正式报价出包需要已批准或已接受的报价版本、真实业务批准引用、当前价格读取权限，以及另一名有资格人员对精确动作的逐次执行批准。报价制单人和执行发起人均不得批准该正式动作。批准绑定动作摘要、对象版本、提供方版本、授权和期限；旧卡片或旧摘要不能批准变化后的动作。

普通跟进仍经过中央工具政策和精确批准记录。当前实现支持三种动作契约：创建跟进任务、更新跟进日期、报价出包。提供方执行实现与跨系统事实由 E5 接入；未配置提供方时不能执行写入。

`prepare` 是 Host 内部调用，输入必须来自受信准备流程，不能把客户端或模型自报的输入摘要当作真实准备结果。浏览器只能查询已有动作、处理有权审批的请求，以及取消或核对原动作。E4 工作流和 E5 提供方准备流程负责创建这些输入。

## 有限策略

管理员配置职责的能力和字段上限，策略负责人再明确接受具体范围。策略只允许创建跟进任务或更新跟进日期，不能自动批准正式报价。

策略固定负责人、身份与权限依据、职责、提供方绑定、客户或商机、关联客户、有效期及次数上限。当前自动路径限于该对象的基础字段，不接受扩大输入来源或客户范围；商机改关联客户后必须重新确认范围。每次调用仍检查负责人和批准所需权限。

自动执行先创建中央工具批准，再根据已接受策略形成精确决定。审批查询明确显示 `origin: policy` 及策略版本，不能将它呈现为人员逐次点击。次数在动作准入时持久记账，同一操作重发不重复计数；取消及发布新策略版本均不清零已用次数。

## 预算、停止和核对

工作区的累计计量由全部 Goal 共享，单个 Goal 不能重复领取完整工作区额度。配额配置变化不清零既有预留和耗用。实际用量由受信计量器提供，异步或无效计量不会被当作零费用，也不能完成结算。

工具承诺提交前取消会释放未用预算并终结 Job。承诺之后只保存取消请求并尽力中断在途调用；没有确定回执时仍显示待核对，并保留原操作和预算。提供方忽略中断且实际成功时，按照成功回执结算，不伪造为未执行。

在途监控继续检查身份、权限、绑定和停止请求。提供方自身的合法写入可能推进业务版本，不能仅据这种版本推进把正常结果当作撤权。新派发仍必须匹配原准备版本，提供方也须在自己的事务中重验源版本和实际人员权限。

核对接口只查询原 `operationKey`，不接受客户端上传的“成功回执”或自报费用，不重新发送写入。已失权人员不能借重复请求读取原结果；有资格人员仍可核对已发生事实。停止本人动作的响应只返回状态和标识，不能借取消操作读取已失去权限的内容。

## HTTP 接口

请求、响应和客户端从[企业 OpenAPI](reference/enterprise-openapi.yaml)生成。写入要求企业会话、同源和 CSRF 检查、`Idempotency-Key`；已有对象更新要求 `expectedStreamVersion`。

| 路径 | 行为 |
| --- | --- |
| `/v2/workspaces/{workspaceId}/execution-configuration` | GET 职责、绑定和当前可见策略 |
| `/v2/workspaces/{workspaceId}/execution-settings` | POST 配置职责能力及字段上限，限管理员 |
| `/v2/workspaces/{workspaceId}/execution-policies` | POST 创建或修订有限策略，限管理员 |
| `/v2/workspaces/{workspaceId}/execution-policies/{policyId}/acceptances` | POST 负责人明确接受 |
| `/v2/workspaces/{workspaceId}/execution-policies/{policyId}/revocations` | POST 负责人或管理员撤销 |
| `/v2/actions/{actionId}` | GET 按当前对象与字段权限读取动作 |
| `/v2/approvals/{approvalId}` | GET 精确动作摘要、批准来源及当前是否可处理 |
| `/v2/approvals/{approvalId}/decisions` | POST 提交逐次决定，要求动作摘要匹配 |
| `/v2/actions/{actionId}/cancellations` | POST 停止请求，返回最小状态信息 |
| `/v2/actions/{actionId}/reconciliation` | POST 查询原操作回执并核对 |

动作请求重发返回同一动作的当前状态，状态可能已随 Worker 推进；不会创建第二个动作或重复扣费。调用方不能复用同一个请求键替换参数。

## 装配与验收边界

本地企业入口装配受保护存储及执行准入服务。提供方解析器和计量器只能由受信 Host 注册；默认缺项会阻止外部执行。Worker 通过 Host 工厂获得同一 Kernel 与 Job 存储能力，没有新增工作流引擎。

`npm run verify:enterprise-admission` 执行权限及 HTTP 检查，`npm run verify:enterprise-admission-postgres` 在独立 PostgreSQL 和合成 HTTP 提供方上验证企业准入与 E3.1 故障协议。快速权限单测可使用内存对象存储；真实落盘、数据库、重启和回执核对另行验收，不能互相替代。结果见[E3.2 验收记录](verification/enterprise-e3-2-2026-11-04.md)。

动态计划、持续规则、真实 Sales/企业微信、平台容量和试点分别由 E4—E8 完成，本包不将合成提供方视为真实外部联调。
