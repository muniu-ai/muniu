# 0012：内核领域边界与执行准入修复

日期：2026-09-28。基线：`69e4dceca40204292fe091d0da715ea8d146a197`。

## 决策与实施范围

OS 负责持久执行、授权、审批、执行证据和恢复控制。业务主数据归应用所有。此次先消除内核中的行业执行规则，并修复通用撤权、敏感控制事实和任务恢复的一致性问题；运行时执行单位、数据库物理结构和插件信任边界保持现有规格。

本次工程子计划包含以下关联改动，完成回归后共同验收：

1. 将询价候选与报价动作 Ledger 移入私有 `@mn/business-execution`。该模块保存必要执行输入引用、预算、承诺和回执，通过通用内核事务维护控制状态。Host 装配其入口，Worker 调用其处理逻辑。Kernel 不依赖应用模块，也不包含行业类型或规则。
2. 在执行启动、恢复、模型请求、工具派发与审批边界检查发起人的当前工作区权限。成员撤销或降为不可操作角色后，未派发操作停止，原批准失效。已开始且效果未知的操作保留核对要求，重新加入工作区不恢复旧批准。
3. 将包含用户正文的核心投影纳入已有加密事实日志。普通事件不再复制这些投影的正文；授权读取和重建仍返回完整内容。备份、维护和企业入口使用同一加密范围。
4. 未知副作用处理按任务的执行关联与租约校验推进，不按行业任务名分支。实际任务与查询投影在同一事务终结，并保留 Execution 的人工核对状态。
5. 现有 0.2 数据通过显式维护升级：本地只升级备份恢复副本，企业在独占维护窗口逐租户提交。只从通过 HMAC 和 CAS 校验的事实构建新加密记录，不信任查询缓存，不改写历史事件。失败前已提交的租户不回滚，新增 CAS 对象和包装密钥也可能保留；未完成的企业升级保持离线。

新模块是第一方执行服务，不是产品插件，也不是新的公共插件 SDK。产品插件仍只依赖已批准的公共契约与 SDK。新增模块保持 private，TypeScript 和工具链版本不变。

## 不变量与采用边界

模型上下文和工具承诺在外部调用前持久化。未知副作用不自动重放；重新授权不能消除效果未知。操作开始前的持久准入是 OS 的权限检查边界，已经准入的在途请求只能尽力取消，不能保证外部系统瞬时撤权。

加密事实日志负责受保护查询状态的重建，不成为新的业务权威来源。事件链完整性校验不能证明数据库从未整体回退，也不能代替接收方的可信回执。历史备份可能包含旧版明文字段，本次不会改写历史事件或声称消除已有外部副本。

OPC、Coding 与签名插件的现有领域仓储仍由 Host 数据端口承载。将 Ledger 移出 Kernel 不等于已经完成这些应用的独立数据库、outbox/inbox 协议或数据格式升级。正式应用 SDK 与物理存储分离需要另行冻结规格，不能把接口草案视为已上线能力。

可信同进程插件可使用宿主权限，本次不提供恶意插件隔离。Coding 的不可变 Spec、Governance、Harness、Gate、Evidence 和必需沙箱约束继续有效。研究候选、全面重写、生产试点和发布不属于本次工程验收。

## 验收

- 撤权覆盖排队、模型在途、等待审批、批准后和未知效果；重新授权后不复用失效批准。
- 固定敏感样本不进入生产配置的明文事件、投影与幂等回执；授权读取、加密重建、备份恢复和密钥缺失处理保持一致。
- SQLite、通用 PostgreSQL 和实际企业 Worker 路径均覆盖两个非行业任务的未知效果结算；物理任务与查询投影一致，陈旧租约提交失败。
- 架构测试禁止 Kernel 引入行业规则，禁止产品插件导入内核事务或业务执行服务；原有业务执行测试随模块迁移保留。
- 执行 `npm test`、`npm run typecheck`、`npm run typecheck:desktop`、`npm run build:desktop`、`cargo test --locked`（在 Desktop 的 Rust 目录）、`npm run verify:enterprise-fixture`、`npm run verify:plugins`、`npm run verify:onboarding-ui`、`npm run verify:opc-ui`、`npm run verify:coding-ui`、`npm audit --omit=dev` 和 `git diff --check`。

fixture 和单元测试不替代真实数据库、模型、网络故障、独立恢复、恶意插件隔离与企业负载试验。验收记录须区分通过、失败、未运行及其原因。
