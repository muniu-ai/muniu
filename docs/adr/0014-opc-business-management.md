# ADR 0014：OPC 持续经营与业务事实

- 日期：2026-10-09
- 状态：采用
- 范围：[OPC 经营管理体系](../proposals/opc-business-management-2026-10-09.md)的 M1，服务和项目型一人公司

## 问题

现有 OPC 以机会捕获、证据和验证决定为终点。已有客户、订单和持续交付无法直接进入，最小收费方案和付费证据也不能承担订单与资金台账的职责。仅修改入口名称会使实际能力与产品承诺不符。

## 决策

OPC 的主入口为经营管理，机会验证保留为客户洞察子流程。M1 记录经营计划、客户、产品版本、报价和订单、交付与客户验收、收支以及周期复盘；每个工作区对应一个经营主体，首批金额统一使用 CNY 整数分。多币种、库存、税票和跨主体汇总另立子计划。

经营事实使用独立于机会的事件流。客户、产品、报价、订单、交付和流水各有稳定标识及显式引用；单个工作区经营版本串行化写入，保证收款分配、退款和订单调整在同一事务校验。首版选择该边界是为了简化一人公司的跨对象一致性；规模增加时必须评估事件流大小、查询成本和写入竞争，再决定拆分方式。

领域规则归属 `plugins/opc`。Host 组合授权、插件状态、事务、受保护事实与幂等回执；Kernel 不引入财务或销售规则。Desktop 和 CLI 只提交同一 `/v2` 契约，不各自计算权威余额。模型不注册经营事实，现有验证 Agent 仍只处理机会上下文。

报价和产品修订保留旧版本，客户确认后订单固定条款。已有订单依据原合同快照登记截止日、期初已收和已交付，不补造报价或历史现金流。付费证据与流水、Agent 成果接收与客户验收分别记录。

收款、退款和费用来自负责人登记的已发生事实，并保留发生时间与凭据依据。退款改变现金和应收余额，减免订单价款另作调整；录错流水通过冲销更正。任何记录都不能声称已经银行核验或客户电子签名。复盘冻结当时的数据版本、期间及指标，迟到事实不改写旧复盘。

经营日期统一按北京时间（`Asia/Shanghai`）确定，审计时间继续使用 UTC。期初截止日包含当天；后续流水、交付和调整必须晚于该日。选择早于期初截止日的余额时，因缺少此前资料而拒绝计算，不能把未知余额显示为零。

经营基础记录可以在没有模型连接时使用；首次调用 Agent 时再配置模型。对外联系、内容发布、签约和资金执行不属于 M1 的台账操作。

## 验收

- 一笔新业务从经营计划、客户、产品报价到订单、交付、验收、部分回款、费用和复盘均可通过 API、Desktop 与 CLI 操作。
- 1,000 元历史订单已收 400 元、已交付一半，可直接登记，600 元为剩余应收，400 元不计入本期现金流。
- 重复幂等请求返回原结果；同键不同请求与过期版本被拒绝；新请求重用引用不能重复成交或入账。
- 金额分配、退款、冲销、调整、日期及来源引用受到校验；不同工作区和租户不能互相引用对象。
- 查询投影删除后，受保护事实可重建；失去读取权限后，旧幂等键不能获取历史结果。
- 产品、金额、权限与桌面流程检查及仓库工程基线通过。实际执行结果另记于验证记录。
