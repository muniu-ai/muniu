# 企业知识、成果与流程

本页说明 E4.3 的 Host 服务与接口。业务事实仍由独立业务聚合及其事件产生；模型报告、内部成果验收和经验启用均不构成客户验收、到账或正式业务批准。

## 来源与保护

知识分为原始资料、业务事实、人员决定、候选经验。原始资料导入必须绑定当前有权读取的业务对象及字段，并声明内容等级。业务事实快照由程序读取指定业务字段生成；人员决定由实际成果验收记录生成。客户端不能通过上传文本选择这两种来源。

每个内容版本不可变，原文、提取结果和来源引用使用受保护 CAS 保存；事件投影保存内容摘要与引用。资料标题、内容和检索结果均检查当前企业身份、对象范围、字段等级及完整来源链。管理员身份不自动获得业务数据权限。派生内容继承来源字段等级；删除正文中的价格字样不能降低其保护等级。

默认资料私有。所有者可按不可变版本共享；共享后仍要求接收人具备来源业务对象及字段权限。新增版本不会自动继承旧版本的共享决定。所有者撤回资料后，旧版本、引用及派生内容的后续读取、检索、模型使用和导出均被阻止。失去业务读取权限的所有者仍可查看最小控制状态并撤回或取消共享。所有者失权不自动撤销其他接收人的独立授权；接收人仍按自身当前权限和原来源权限读取。

导入上限为 8MiB 原始文件。沿用有资源上限的 TXT、Markdown、JSON、CSV、DOCX、XLSX 和 PDF 提取器；完整、部分提取、不可读取状态分别返回。无 OCR 能力。引用定位到页码、段落或单元格，并绑定版本和块摘要。资料响应提供当前有权读取的来源引用，客户端可逐层回查原始来源；成果正文显示资料名称、版本和定位，不显示内部权限字段。模型上下文只包含字节上限内选中的完整块，同时给出提取覆盖范围。模型报告中的资料引用必须来自本次已持久保存的上下文；伪造定位或在完成判断中漏掉引用会被拒绝。

## 成果与经验

完成节点的报告可固定为候选成果。人员验收需要当前资料权限、成果版本、工作版本、完整验收条件和确认说明；仅当前范围的末端节点可作为最终成果。所有末端成果验收后工作才完成，仍有在途节点或待核对费用时不能完成。验收决定保存确认人、条件、成果版本和说明，不改写业务聚合。

经验从已验收成果提出，保存为不可变候选版本。候选可供有权人员查看，但不会进入知识检索或模型上下文。管理员须同时具备来源读取权限，并确认精确内容摘要后才能启用。停用后停止检索和模型使用；有权人员仍可精确读取、核对引用或导出该经验用于审阅。以该经验为来源的派生内容继续检查其启用状态。回退通过重新启用原不可变版本完成。来源撤回或权限变化仍可阻止已启用经验传播。

## 五套流程与在途版本

Business 插件贡献商机跟进、方案报价、项目交付、应收跟进和经营复盘五套流程。每套包含建议资料类型、分析／复核／整理阶段、验收条件和必须由人员决定的事项。阶段建议不限制动态任务图的节点数量；所有节点继续使用 E3/E4 的同一持久执行、预算和授权体系。

管理员发布新版本，再明确选择启用、停用或回退。发布版本不会自动启用。首期每工作区每套流程最多保存 100 个版本，达到上限时在写入前拒绝继续发布；原版本仍可读取或回退。工作范围固定流程标识、版本和摘要；新工作只能采用当前启用版本，已创建的工作不会因流程更新而替换绑定。只有在绑定版本已不再启用时，尚未授权的旧草稿才需要管理员重新启用该版本或由人员修订范围。已授权工作继续按原版本执行。新配置不能删除第一方必需验收条件、改变人员决定边界或引入任意代码。

正式报价出包、跟进回写及其他业务写入仍需 E2/E3 的业务与执行批准；提供方执行由 E5 接入。

## 接口

请求和响应由 API schema 生成。所有接口要求当前企业会话；POST 要求 `X-CSRF-Token`。所有状态变更，包括资料导入、共享、撤回、成果固定与验收、经验及流程配置，另需 `Idempotency-Key`；已有对象变更需要 `expectedStreamVersion`。只读 POST 不产生业务写入，因此不要求幂等键。

| 入口 | 用途 |
| --- | --- |
| `/v2/workspaces/{workspaceId}/knowledge` | 导入原始资料或新内容版本 |
| 同入口下 `/reads`、`/search`、`/citations`、`/exports` | 精确版本读取、检索、引用核对及 DOCX/PDF/XLSX 导出 |
| 同入口下 `/sharing`、`/documents/{documentId}`、`/documents/{documentId}/withdrawals` | 版本共享、最小控制状态与撤回 |
| 同入口下 `/business-snapshots` | 从获准业务字段生成事实快照 |
| `/v2/artifacts`、`/v2/artifacts/{artifactId}`、其下 `/acceptances` | 固定、读取和验收候选成果 |
| `/v2/artifacts/decision-materials` | 把已存在的验收决定固定为可引用资料 |
| `/v2/artifacts/{artifactId}/experiences`、`/v2/experiences/{experienceId}`、其下 `/decisions` | 提出、查看、启用或停用经验 |
| `/v2/workspaces/{workspaceId}/workflows`、其下 `/versions`、`/reads`、`/{flowId}/selections` | 流程目录、发布、读取和启用版本 |

精确方法、请求和响应见[权威 API schema](https://github.com/muniu-ai/muniu/blob/main/packages/contracts/src/enterprise-api-schema.ts)。表中控制状态、成果与经验读取、流程目录使用 GET；其余使用 POST。`/reads`、`/search`、`/citations`、`/exports` 和流程 `/reads` 为只读 POST。资料变更的 `expectedStreamVersion` 对应文档控制流，成果验收另需 `expectedGoalVersion`；经验决定与流程变更分别使用其当前控制流版本。

工作创建、范围修订及规则工作配置可选填 `workflow`，其值为流程目录中的精确版本引用。权限不足不返回原始受保护内容；版本或幂等冲突返回 409，来源撤回返回 410。仅声明 schema 不会装配服务；未配置对应运行时的 Host 返回 503。本地企业入口已统一装配知识、成果、经验和流程服务，界面由 E6 接入。

## 验证与离线评测

`npm run verify:enterprise-knowledge` 执行实际 Host、Worker、知识、成果、流程与引用测试。`npm run verify:enterprise-knowledge-postgres` 复验 E3/E4.1/E4.2，并验证知识双连接幂等、成果、经验、流程及投影重建；该命令会创建并清理独立 PostgreSQL 测试容器。低内存环境需按[开发指南](development.md)串行执行，并为 Node 设置内存上限。

`npm run verify:operating-evaluation -- --self-test` 只验证冻结任务的计分和证据检查逻辑。它不会执行真实模型或人员评测，也不会把合成记录判为真实质量通过。正式记录使用：

```sh
npm run verify:operating-evaluation -- --evidence /absolute/evaluation/records.json --output /absolute/evaluation/report.json
```

命令仅在报告 `passed: true` 时以 0 退出；生成了报告不表示通过。`complete` 表示记录齐全，`thresholdsMet` 表示统计门槛达到；合成数据的 `qualification` 恒为 `synthetic_only`、`passed` 恒为 false。`pilotPassed` 恒为 false，试点须独立验收。

记录必须绑定 E0.2 冻结文件摘要、模型版本、提示摘要、输入和权限摘要、工具与计价版本、独立复核人和基线操作者。字段实例及反例在 `scripts/test/operating-evaluation.test.mjs`；该文件全部为合成数据，不得用于正式成绩。记录文件上限为 16MiB；大日志按 64KiB 块串行核验摘要。原始日志以相对路径和 SHA-256 引用，必须位于记录文件目录内；输出文件不得已存在。

校验器要求两模式各 30 项任务、每项三轮、对应人工基线及全部冻结安全任务。开发集和留出集分别统计，每条流程分别报告；失败、返工与未知费用不能从统计中删除。安全检查也记录独立状态空间、输入摘要、复核人与费用；纯程序检查明确标为未调用模型。费用未知、记录缺失、安全失败、人工自审、输入变化或留出调参均阻止正式通过。人工时间按每任务三轮平均后与对应基线比较，包含准备、审核、纠错、返工及分摊时间。日志摘要验证用于检查记录完整性，不能替代独立人员对结论和计时真实性的复核。

真实模型配置、人工基线和复核人员尚未提供，因此当前不具备真实离线质量成绩。E7 的容量、真实双系统评测和 E8 的试点观察仍有独立门槛；任何本地工程检查不能代替这些验收。
