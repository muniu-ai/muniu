# 能力与验证状态

本文帮助评估木牛 Agent OS 0.2 的使用范围。源码实现、某轮测试通过、可公开分发的安装包和生产部署验收是不同结论。

## 当前源码提供什么

| 范围 | 已有入口与行为 | 使用条件与边界 |
| --- | --- | --- |
| macOS 本地使用 | Desktop 管理 Host；CLI 连接同一 Host；首次设置可选择经营记录、内置模型或外部 Agent | 内置模型需 BYOK，密钥使用 Keychain；外部 CLI 使用自身账号，仍须通过安装、登录、身份和执行检查 |
| OPC 经营管理 | 经营计划、客户、产品版本、报价订单、交付验收、收支和复盘 | 服务与项目型业务的 CNY 人工台账；基础操作无需模型，见[经营指南](./guides/business.md) |
| 机会验证子流程 | 捕获、研究、访谈、证据和人工决策 | 人工确认承诺与最终决策；不自动外联、发送报价或收款 |
| Coding 研发任务 | 仓库、任务、规格、检查、审批与成果 | 需要的沙箱不可用时停止；外部 Runner 需显式选择并确认身份 |
| 目标与验收 | 统一委派、不可变计划、执行者推荐、预算预留、状态同步及逐项人工接收 | 单 Agent 可选择内置执行者、Codex CLI 或 Claude Code；团队须显式选择。当前均保留一个完整交付项，见[任务指南](./guides/goals.md) |
| 持久团队执行 | P2 工作树新增研究汇总、经营方案、代码交付三个固定模板；独立节点、持久 Job、结果汇合及人工决定 | 首版仅使用具备费用控制的内置模型；不自动选择团队或自主改变节点。Host 全流程及完整基线仍在验证，见[P2 记录](./verification/agent-os-p2-2026-10-10.md) |
| 资料与成果 | 委派保存受保护 Asset 版本引用，支持 TXT、Markdown、CSV、JSON、含文本的 PDF、DOCX、XLSX；保留段落、页码和单元格定位 | 长资料按目标与验收条件选段，不能据此声称完整阅读。撤销来源后阻止后续读取和外发；已发送到外部的数据无法撤回。见[资料指南](./guides/materials.md) |
| 业务对象委派 | 客户、订单、交付、复盘可交给 Agent，绑定获准业务事实版本 | 联系方式不自动外发；领域规则计算金额，Agent 只提供分析。任一台账事实变更会保守地使旧业务引用失效 |
| 工作台与导航 | 工作台、任务、经营、资料与成果为主要入口；搜索与卡片携带对象位置，Shell 共享事件订阅与断线状态 | P0 已完成本地验证，见[验证记录](./verification/agent-os-p0-2026-10-10.md)；其他阶段按各自记录判断 |
| 插件扩展 | 公共 SDK、受信签名制品、工作区启用和生命周期 | 生产插件是进程等价的可信代码，不支持将任意不可信插件当作隔离应用运行 |
| 企业部署 | PostgreSQL、S3、Vault/KMS，多 Host 与 Worker | 需配置身份、网络、密钥与备份，并完成目标环境验收；测试部署不等于生产认证 |
| 中断恢复 | 持久任务、事件、工具承诺和人工核对 | 未知副作用不自动重放；事件链不能证明数据库从未整体回退 |
| 工业询价参考应用 | 与独立 Sales 应用配套的受控候选和报价出包 | 单独的依赖、合成样本与发布门禁，见[专项入口](./industry-delivery/README.md) |

## 最近的工程验证

[2026-10-10 Agent OS P2 验证](./verification/agent-os-p2-2026-10-10.md)记录固定团队契约、纯编排规则、节点协调和目标服务的聚焦检查。Host 全流程、桌面接线和完整基线尚未完成本轮验收；工程测试不代表团队质量或成本改善。

[2026-10-10 Agent OS P1 验证](./verification/agent-os-p1-2026-10-10.md)记录版本化资料、业务对象委派、上下文预算及撤权保护。本轮 889 项 Node 测试、9 项 Rust 测试和受影响 UI 门禁通过；真实企业容器阶段因依赖下载超时未完成。

[2026-10-10 Agent OS P0 验证](./verification/agent-os-p0-2026-10-10.md)记录首次设置、对象直达、共享刷新和评测基础的本轮状态。60 项合成任务与 15 项安全恢复场景已冻结，比较器测试通过；真实模型基线与团队效果仍未测。

[2026-10-10 统一 Agent 调度验证](./verification/roi-agent-scheduling-2026-10-10.md)记录内置及外部 CLI 调度的工程证据。外部 CLI 费用不能实时强制限额，推荐参数尚未经过真实业务基准校准。

[2026-10-09 OPC 经营管理验证](./verification/opc-business-management-2026-10-09.md)记录服务和项目型经营首版的金额、权限、恢复和桌面流程检查；渠道执行与经营 Agent 不在该轮范围内。

[2026-10-09 目标与成果验收验证](./verification/agent-os-s1-2026-10-09.md)记录本次 S1 的代码范围、测试环境及未完成项。它不代表总体多 Agent 提案或真实模型质量已经验收。

[2026-09-28 领域边界与执行准入验收](./verification/application-boundaries-2026-09-28.md)对应实现提交 `07e84ce`，记录了 700 项测试、类型与桌面检查、Rust 测试、真实 PostgreSQL/S3/Vault 企业集成和显式加密升级检查。Kind 在镜像导出阶段中止，未完成沙箱断言。

这是该提交与测试环境的记录，不是对之后所有改动的持续保证。修改代码后按[开发指南](./development.md)选择检查，交付时记录实际结果。文档构建和源码合并也不代替安装包、沙箱或目标部署的验收。

## 尚不能据此作出的结论

- [经营到交付优化计划](./proposals/agent-os-delivery-2026-10-10.md)已整体实现，或业务候选应用、有限返工、团队技能及主动跟进已可用。P1 已完成源码和本地验证，企业容器复验仍受网络阻塞；P2 固定团队正在集成验证，P3—P5 尚未完成。
- 已通过通用企业生产负载、真实模型质量和费用评估。
- 团队首次验收率已达到单执行者基线，或每个已验收成果的费用或人工时间已降低 20%。
- 同进程插件能够隔离恶意代码，或已发往外部系统的数据能够被撤回。
- 事件和密钥从任意独立备份恢复后都可无条件继续执行。
- 正式应用 SDK、应用独立数据库或研究候选已经整体上线。

当前架构与边界见[架构说明](./architecture.md)和[ADR 0012](./adr/0012-application-boundaries.md)。发布需要补齐[技术与发布契约](./TECHNICAL_DESIGN.md)及对应平台的验收证据；历史未完成项不因文档整理而改变。

模型接入新增 Kimi 中国区与 Qwen 百炼北京区，设置页和 `doctor --workspace` 可分项检查外部 Agent 调度条件。模型和外部账号的支持范围、未验证项见[模型与外部 Agent](guides/agents-and-models.md)及[验收记录](verification/agent-model-connectivity-2026-10-09.md)。
