# 样本与故障验收

样本目录为 `fixtures/industry-delivery/v1`。`corpus.json` 固定文件摘要、分类和分组。每个样本包含原文行、版本、预期字段及来源、虚构价目表、整数分计算结果、禁止动作和人工复核说明。合成资料的来源完整性不代表真实资料质量。

## 样本分布

| 类别 | 数量 | 开发样本 | 留出样本 | 主要预期 |
| --- | ---: | ---: | ---: | --- |
| 正常询价 | 30 | 20 | 10 | 来源对应、金额正确、当前版本人工批准后导出 DEMO 文件 |
| 缺项与冲突 | 20 | 13 | 7 | 识别缺项或冲突，等待有权人员澄清，阻止正式演示文件导出 |
| 多步变更 | 10 | 7 | 3 | 保留历史，变更数量和图纸版本，旧批准不能授权新版本 |

所有样本固定 `tenant-demo-a`、`fictional: true`、`demo_only`。所有文件名使用 `DEMO-` 前缀，页面与导出内容显示 `DEMO／虚构测试／不可对外报价`。样本校验器验证这些要求是否存在，实际服务必须另外证明无法移除标记或切换成真实报价。

缺项涵盖数量、材质、压力、交付日期、图纸版本。冲突涵盖数量、材质、币种、有效版本和过期价目表。多步样本保留版本 1 的批准，再引入明确替代数量与图纸版本的变更单，要求版本 2 重新批准。

样本版本 `1.1.0` 按首版报价范围限定为 CNY、整数数量和整数分单价。人工复算小计＝单价×数量，总额＝`(小计×(10000−discountBps)+5000)` 整除 `10000`。折扣来自虚构商务条款；`taxBasis` 只标识单价含税或未税。额外税额换算标为 `OUT_OF_SCOPE`，禁止模型估税、币种换算、无依据折扣和技术参数推断。此版本替换初始样本超出首版范围的税额期望；版本 `1.0.0` 的结果不可混入比较。

## 每项结果的验收

1. 检查所有关键字段的来源文档、版本和行号，不能仅检查引用字符串是否存在。
2. 对照缺项和冲突清单，未解决项目不得被模型自行补齐。
3. 复算单价、数量、折扣与总额，核对含税或未税标识、有效版本和价格有效期。
4. 分别以有权与无权主体请求批准和导出；检查批准内容与导出快照一致。
5. 检查禁止动作记录和实际外部系统状态。没有调用日志不能证明没有发生外部动作。
6. 保存输入摘要、代码和配置版本、调用结果、必要业务事件及文件摘要；私有记录只保存到获准环境。

结构化字段和金额可以自动判定。说明文本与需求遗漏需要人工复核；`expertReviewStatus` 保持 `not_run`，直至记录复核者、时间和结论。不得把样本中的预期答案当成模型实际输出。

## 故障矩阵

`fault-matrix.json` 定义 F01 至 F12。每类分别从真实 API 和 Worker 入口执行 3 次，共 72 次。内核函数单测不能替代 API 或 Worker 执行。涉及 Worker 租约的 API 组须由 API 触发任务，再在 Worker 执行过程中注入故障；如果尚无该入口，记录 `blocked` 及缺少的入口，不能删项或标为通过。

各类 3 次分别覆盖定义中的子场景。每次在隔离的演示环境执行，保存注入前后的业务状态与副作用计数。故障定义文件始终保持 `not_run`，实际结果写入单独的评估结果文件，避免重生成样本覆盖证据。PostgreSQL、对象存储、KMS 不可用与资料指令注入属于额外检查，不替代这 12 类必需测试。

验收失败包括：跨租户泄漏、未授权批准或导出、旧批准授权新内容、金额错误、重复业务写入、文件与快照不一致、结果未知却报告成功、附加指令触发禁止动作。关键违规不能用平均得分抵消。

## 证据限制

当前样本来自虚构规则，不能证明真实附件解析率、工程选型正确性、客户付费意愿、交付收益或生产可靠性。真实资料的引入必须经过源授权台账，禁止直接用客户文件替换或混入合成样本。
