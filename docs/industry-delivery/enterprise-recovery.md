# 企业部署与恢复验收

本手册描述工业询价联合发布需要补充的验收条件，并引用已有 OS 运维入口。尚未执行真实生产恢复演练，不给出已达成的 RPO、RTO 或可用性承诺。完整 OS 运维约束见[企业运维](../enterprise-operations.md)；0.2 的隔离边界见[硬切换 ADR](../adr/0011-agent-os-v2-hard-cutover.md)。

## 上线前条件

- 发布清单填写 OS、Sales、插件、动作目录、数据库迁移、模型配置、OCI 镜像及前端资源的版本和摘要；Host 与 Worker 的 lock 保持一致。
- PostgreSQL、对象存储、KMS、身份提供方和保留策略可用；凭据由受控配置注入，不放入仓库、测试结果或命令行。
- 两个 Host、两个 Worker 的跨租户、并发、租约、权限撤回和故障恢复测试已有可核对证据。
- Sales 业务批准版本、导出快照和文件摘要已联合验收；前端显示的状态与服务端一致。
- 已记录数据授权、业务验收负责人、数据保留期限和恢复责任人。未完成 P5 时，真实租户准入继续关闭。
- 插件属于与 Host 进程等权的可信代码。验收资料不得把插件边界描述为沙箱。

这些条件是准入要求。清单存在不代表条件已满足，独立门禁脚本也不替代 API 的运行时拒绝逻辑。

## 已有 OS 检查命令

在隔离的部署验收环境执行，`HOST` 替换为已授权目标：

```bash
curl --fail http://HOST/v2/health
curl --fail http://HOST/v2/readiness
npm run verify:enterprise-fixture
npm run verify:enterprise-e2e
npm run verify:kind
```

`verify:enterprise-fixture` 与真实依赖验收分开记录。Compose 的开发 Vault 使用内存密钥，暂停恢复测试不能证明生产 Vault 重启后的恢复能力。Sales 的健康、备份及恢复入口须按实际实现补充，未配置时 P5 保持阻塞，不猜测命令。

## 联合备份范围

备份覆盖 OS 的事件与加密投影事实、Sales 业务数据库、对象存储内容与版本、报价批准记录及导出文件、engine/plugin lock、动作目录、部署清单、KMS 标识及撤销记录。只备份事件表或只保存导出 PDF 都不足以恢复批准语义。

OS 与 Sales 分属不同事务边界，必须记录恢复检查点和关联标识，说明检查点之间未完成请求的处理方式。当前没有证据证明两库可作全局原子快照，不能宣称恢复后自动一致。KMS 恢复不得复活已经依法撤销的密钥访问。

## 恢复演练顺序

1. 在隔离环境恢复指定联合清单对应的数据库、对象存储和密钥访问配置；保持入口与 Worker 停止，真实租户准入关闭。
2. 以只读方式验证版本与摘要，确认备份中的批准版本、CAS 对象与导出文件可对应。缺失、篡改或无法解密时停止，不跳过校验。
3. 按已有运维要求执行 OS 离线校验；Sales 必须有对应恢复校验结果。尚无实现时记录阻塞。
4. 对账恢复检查点间未完成的业务请求。结果未知的动作保留人工核对项，不重放外部副作用。
5. 检查旧审批不能批准新内容、历史正式文件仍对应原批准快照、已撤权主体无法访问恢复后的对象。
6. 在演示租户执行 API 与 Worker 故障用例，记录恢复时长、缺失或重复对象数和失败项。所有必需断言通过后，才提交技术准入证据。

已有 OS 离线校验命令如下。执行前停止所有共用目标数据库与 CAS 前缀的写入者，并按企业运维文档配置专用数据库权限与 `MN_MAINTENANCE_ACTOR`：

```bash
npm run maintenance:enterprise -- verify --offline --database DATABASE
```

`rebuild` 和 `gc` 会改变状态，本验收包不自动执行。维护失败可能使目标数据库保持离线；按企业运维文档核对维护事件、权限和对象状态，不能盲目重启服务或重投任务。

## 版本切换和失败处理

蓝绿切换以整份联合发布清单为单位。新环境只读校验通过后，停止旧环境接收新任务，排空可确认任务，再切换流量与 Worker 领取权限；不得混用不同 engine/plugin lock 消费同一队列。

新版本已经写入不兼容数据后，不自动把流量切回旧版本，也不加载 pre-0.2 状态。需要明确的兼容性证明或隔离恢复方案。恢复失败、HMAC 失败、文件摘要不一致、KMS 不可用或存在无法核对的提交时，继续关闭真实准入，并保存事件与副作用证据。

## P7 真实客户条件

当前 `blocked` 原因是没有获准的真实客户样本，也没有实际业务复核、使用效果和付费证据。允许在演示租户完成技术验证；不得据此发布真实客户案例、收益百分比或行业准确率。引入真实资料前记录来源权利、处理目的、模型供应方、保存期限、删除责任和业务验收人，再单独安排真实场景验收。
