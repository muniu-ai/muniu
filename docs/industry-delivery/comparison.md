# P6 同场比较契约

当前只提供比较输入、适配要求和结果汇总工具。固定工作流、DSH、ADP 与木牛的同场执行均未完成；不能从资料中的能力描述推断测试结果。

## 固定条件

四组使用相同样本版本、资料范围、业务规则、人工批准要求和禁止动作。记录模型名称与具体版本、模型参数、提示词摘要、工具与代码版本、部署配置、业务批准接口、资源预算和每次执行费用。无法使用相同模型时，单列为配置差异，不归因于框架。

| 适配器标识 | 边界 | 必须记录 |
| --- | --- | --- |
| `fixed_workflow` | 固定步骤加模型提取，沿用相同报价规则与批准服务 | 固定流程定义、模型配置、额外代码摘要 |
| `muniu` | 实际 OS 与 Sales 联合版本 | 两仓库提交、lock 摘要、动作目录、批准与导出实现 |
| `deepseek_harness` | 独立环境使用固定上游版本，不向木牛复制或导入上游代码 | `ddefc45fbc7f8e46dd73185e68295696d1297887`、运行环境、业务适配代码与额外治理成本 |
| `adp` | 实际选定套餐和平台版本，公开文档只作为配置依据 | 套餐、核验日期、应用导出或配置摘要、模型、外部补充服务、实际费用 |

DSH 的比较版本不改变仓库允许改编源码的固定提交。公开比较用的后续版本只能在独立环境运行，不得成为当前代码引入来源。

适配器接收 `caseId`、合成 tenant、输入文档、冻结配置摘要和入口标识；返回实际字段、来源、澄清事项、报价快照、批准事件、导出文件摘要及副作用记录。不得向被测模型提供 `expected` 字段。故障适配器还须暴露可重复的注入步骤、清理步骤与注入成功证据。

## 状态语义

| 状态 | 含义 | 能否计为实测通过 |
| --- | --- | --- |
| `not_run` | 未执行，没有实际结果 | 否 |
| `documented` | 仅有可定位的公开文档支持 | 否 |
| `unknown` | 当前证据不足，无法判断能力或结果 | 否 |
| `blocked` | 明确缺少执行条件，须说明原因 | 否 |
| `passed` | 实际执行，必需断言全部通过，关键违规为零，证据已记录 | 是，但仅限该项场景 |
| `failed` | 实际执行并出现不满足断言的结果 | 否 |

缺少 ADP 凭据时保持 `not_run`，不得登录、购买、上传资料或调用。环境确认后仍缺少某项权限或套餐能力，可记录 `blocked`。仅有官方文档的条目使用 `documented`，不能据此声称本场景通过；未找到机制使用 `unknown`，不能写成不支持。

## 结果格式与执行

复制 `benchmark-results.template.json` 到获准的私有评估目录，填写 `runs`。一组最多包含 60 个样本项与 72 个故障项；重复测试标识会被拒绝，重跑采用新的完整结果文件保存。

```json
{
  "adapter": "adp",
  "testId": "DEMO-RFQ-001",
  "status": "not_run",
  "reason": "尚未取得适用套餐的执行环境"
}
```

实际执行的 `passed` 或 `failed` 还必须提供：`runId`、`executedAt`、`configurationSha256`、至少一个含 `path` 与 `sha256` 的 `evidence` 条目，以及 `metrics.requiredAssertions`、`metrics.passedAssertions`、`metrics.criticalViolations`。可另记准备成本、复核时间、返工时间、延迟和资源费用，缺少测量时不得填 0 代替未知。

```bash
node scripts/industry-delivery-summary.mjs /absolute/private/results.json --verify-evidence
```

证据相对路径按结果文件所在目录解析。默认模式仅校验元数据；`--verify-evidence` 才核对文件存在与内容摘要。摘要核对不验证证据真实性或断言充分性，仍须审查实际输入、输出及副作用。

汇总按每个适配器 132 个必需项目显示缺失项，文档项不计入实测。脚本不生成排行榜，不自动认定竞争优势，也不把合成测试转换成生产准入。20 个留出样本执行前要冻结配置；如果适配器对留出结果做过优化，必须更换独立评估集。
