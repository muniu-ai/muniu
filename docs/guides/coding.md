# 创建并执行 Coding 任务

Coding 将仓库中的变更组织为任务、候选差异、检查、审批和成果。开始前，完成[快速开始](../quickstart.md)，在当前工作区启用 Coding，并准备一个你有权操作的本机 Git 仓库。

真实执行需要可用模型连接和受支持的 Coding sandbox。本机默认使用 macOS 的 `/usr/bin/sandbox-exec`。仓库登记、任务创建和只读样例成功，都不能证明实际执行条件已经满足。

## 1. 登记仓库

点击“委派任务”，选择“研发”，再点击“登记仓库”（已有仓库时显示“添加仓库”）。也可从“Coding → 工作区仓库”打开登记窗口。

桌面版点击“选择文件夹”，选中本机已有的 Git 仓库，再点击“登记并选中”。也可粘贴仓库绝对路径，例如 `/Users/你的用户名/Projects/仓库`；浏览器版使用路径输入。只有 GitHub 等远程地址时，先将仓库克隆到本机。

登记成功后自动选中该仓库，已输入的任务描述会保留；取消登记不会创建记录。当前工作区已有相同路径时复用原记录。连接中断时可在同一窗口重试，也可关闭后重新打开；同一路径会沿用本次请求，避免重复登记。

仓库列表显示名称和路径后，登记完成。此操作只保存路径，不读取或修改仓库；执行任务时还会检查访问权限。一个工作区可登记多个仓库。

如果首次向导只选择了 Coding，“第一个仓库或任务”目前创建的是仓库记录。请填仓库绝对路径，再按下一步创建任务。

## 2. 创建待审阅任务

点击“委派任务”，选择“研发”和“任务仓库”，输入边界明确的目标、验收要求和参考资料，再点击“准备执行计划”。仅登记一个仓库时会自动选择；刚完成登记时会选中该仓库。有多个仓库时，提交前确认“任务仓库”是否正确。

以下是任务描述示例，请按实际仓库修改：

```text
为事件游标过期场景补充回归测试。只修改相关测试文件，保留现有未提交内容，并说明测试结果。
```

计划准备后，先核对目标、仓库、模型和执行额度。此时尚未生成代码差异，“只读仓库检查”处于“待检查”属于预期状态。准备计划不自动开始 Agent 执行。

## 3. 发起真实执行

在统一任务页点击“确认计划并启动”，由内置 Agent 按已确认的范围与额度执行。会话、执行状态和最终验收都在同页显示，操作方式见[任务指南](./goals.md)。这一步可能调用模型、读取仓库并在隔离副本中生成变更。

已有研发任务也可在“Coding → 打开任务”中发送消息，选择本轮执行方式。外部 Codex CLI、Claude CLI 仍从该入口调度，沿用现有就绪检查；统一任务计划目前使用内置 Agent。

会话显示“已提交，等待执行”或后续执行状态。生成候选后，在任务中查看“差异”“检查”和“审批”；存在完整差异时，可展开“查看完整 Diff”。检查通过后仍需人工审批，不能把检查结果视为已经授权写入源仓库。

遇到审批请求，打开“收件箱”，核对意图、目标资源、影响范围和有效期，再选择批准或拒绝。执行完成后检查成果与“下一步”，以实际结果判断是否达到任务目标。

## 4. 处理阻塞

- 检查未通过时，Gate 失败最多自动修复 3 次，总执行时长默认上限为 3600 秒。达到上限后需要人工决策。
- “执行已暂停”或“执行已中断”时，先处理页面显示的原因，再使用“恢复执行”。存在用量待核对或超支时，界面可能只允许终止本次执行。
- “结果需要人工核对”表示外部结果未知，不能直接恢复或重复执行。按[故障排查](../troubleshooting.md#执行需要人工核对)核实结果。
- sandbox 不可用时会拒绝执行，不能改为无隔离执行。

专业视图可展开“高级执行设置”，查看 Harness 摘要、候选数和剩余预算；两种视图的业务行为相同。

## 使用外部 Runner

首次任务优先使用默认内置 Agent。选择 Claude CLI 或 Codex CLI 前，在“技术配置 → 集成”启用对应 Runner，并核对可执行文件的绝对路径、版本和摘要。文件变化后必须重新确认。

外部 Runner 需要官方原生安装的 macOS Mach-O CLI，npm 或 shebang 包装脚本不被生产 Worker 接受。Runner 不接管木牛的模型连接、Prompt、Skill 或历史会话。在设置中先查看[外部 Agent 调度检查](agents-and-models.md)，具体配置命令见 [CLI 参考](../reference/cli.md)。
