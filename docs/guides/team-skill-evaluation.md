# 团队技能试用与评测

团队技能保存已经接收的固定流程及角色说明。它不携带原目标正文、模型连接或执行授权。试用会创建新目标，重新选择资料、模型和预算；用户批准计划后执行。计划固定技能版本，后续启用、停用或回滚不改变在途任务。

## 建立和试用

1. 完成团队目标并接收全部交付项，保存目标、计划和成果集合的版本及摘要。
2. 在技能目录保存流程，填写角色说明。若说明含来源摘录，明确关联受保护资料；撤销来源后，技能不能继续读取或用于新执行。
3. 从技能详情发起新目标试用。角色文字不能增加工具权限、跳过人工决定或替代 Coding 的 Spec、Gate 与候选批准。
4. 修改技能时创建新版本。工作区所有者通过带版本检查的命令启用、回滚或停用。来源不可用时，目录只显示安全占位和允许的停用入口。

## 离线评测导入

首批评测固定使用 `agent-os-delivery-1.0.0` 的 60 个合成任务：开发集 40 个、留出集 20 个，另含 15 条安全与恢复检查。数据集和基础报告格式见[交付评测基线](https://github.com/muniu-ai/muniu/blob/main/benchmarks/agent-os-delivery/v1/README.md)。不得将留出任务用于调参。

先登记技能版本、模型快照、提示词、策略、资料与预算摘要，以及基线和候选实现提交。登记产生固定 `evaluationId`、`configurationDigest` 和 `frozenAt`。评测报告必须使用同一组字段，覆盖两组全部任务和安全检查；任务开始时间不得早于冻结时间或晚于提交时间。

报告与证据均上传为受保护 JSON 资料。报告在原成对比较格式上增加 `evaluationId`、`skillRef`、`executionMode`。每份证据 JSON 使用以下字段：

- `format`：`muniu.skill-evidence.v1`。
- `evaluationId`、`skillRef`、`executionMode`、`configurationDigest`：与登记记录一致。
- `resultsDigest`：对报告 `arms` 中递归移除 `evidence` 字段后的内容计算规范 JSON SHA-256；仓库私有编排模块提供 `teamSkillResultsDigest(report)`。
- `method`：`human` 或 `deterministic`。人工复核写入当前提交者的 `reviewer`；确定性检查写入检查名称 `check`。
- 实际观察、判定或检查输出。证据应足以复核相应结论，不能只用模型自评分。

先构造两组结果，再计算 `resultsDigest` 并保存证据文件。用证据文件原始字节的 SHA-256 填写报告各项的 `artifactSha256`，最后保存报告。提交时同时提供报告资料引用及每份证据的资料引用、字节摘要和判定方法。修改结果后必须重新生成证据；不能复用旧摘要。

Host 检查固定版本、来源权限、证据绑定和统计门槛。人工与外部确定性证据由所有者导入，接口不将导入动作称为已运行实验，也不替代对证据内容的人工复核。原始证据仍可回源检查。报告单文件上限为 4 MiB，单份证据为 1 MiB，证据总量不超过 16 MiB。

## 质量门与推荐

只有安全与恢复检查全部通过、留出集首次验收率不低于基线，且每项已验收成果的可比费用或人工操作时间至少改善 20%，报告才可能通过质量门。未知费用单列，不按零计算。报告缺项、配置不一致、模型评分、调参使用留出任务或证据撤权均不能通过准入。

`test_fixture` 仅验证导入和计算流程，即使统计达标也不能启用推荐。仓库目前没有真实模型质量报告，不能据此宣称已经达到改善目标。

已通过真实评测的版本仍需所有者显式启用。Host 按新目标的插件、资料槽和交付要求筛选建议；用户明确采用后生成新计划，并继续批准执行。来源、证据或能力失效、停用后，不再给出该建议。报告中的模型和资料配置决定结论的适用范围，不保证不同配置下取得同样效果。
