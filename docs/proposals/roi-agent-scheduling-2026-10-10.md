# 经营与研发统一 Agent 调度

状态：按用户要求实施，默认质量优先。范围为当前支持的经营、机会验证与研发任务，执行者包括内置 Agent、Codex CLI 和 Claude Code CLI。没有 CLI 或未完成适配的产品不显示为可执行候选。

## 执行与决策

任务支持自动推荐和人工指定。计划冻结执行者、模型或 CLI 身份、候选比较、算法版本、数据依据、预算及批准范围。开始前重新核对配置与授权；历史统计更新不能偷偷更换已经确认的执行者。失败或结果未知时不自动换 Agent 重做外部操作。

调度先检查插件、身份、能力、币种和预算，再比较验收质量、费用与耗时。默认质量优先；提供均衡与成本优先选项。历史成功只统计用户已验收的成果，不能把进程退出或模型答复当作质量成功。样本按工作区、任务类型、负载分组和执行者版本隔离，采用保守的成功率下界；没有足够样本时显示依据不足，不编造准确率。

成本包含执行费、用户给定的时间成本与失败返工风险。提供预期任务价值时计算估计净收益及 ROI；没有价值输入时只比较达到质量要求的预计总成本，不把成本评分称作真实 ROI。外部 CLI 的费用未知不能当作零；自动调度只采用可比较的费用依据，人工选择可明确接受费用待核对。外部执行完成后必须登记账单或订阅分摊用量，才能结算并验收。

## 运行边界

研发沿用 Spec、Governance、Harness、Gate、Evidence 和受控副本。经营 CLI 使用隔离任务目录，提交明确资料并保存答复，不授予账目修改或外联权限。两者均保留 CLI 文件身份核对、中央工具批准、调用前承诺、父进程监督与结果未知时禁止重放。CLI 自带账户与木牛模型连接分别呈现。

## 验证

TDD 覆盖质量优先排序、样本不足、费用未知、币种隔离、配置变化、人工指定、重复请求、拒绝批准、取消、未知结果与账单核对；以真实 Host/Worker 隔离测试覆盖经营和研发的内外部执行计划。界面验证推荐理由、人工覆盖、费用核对和成果验收。执行仓库完整工程基线与相关 UI 检查，记录环境缺失。

## 专利研究

另行整理内部技术交底草案和实验协议，不提交申请、不远程公开。检索重点为既有成本质量路由与本方案在执行承诺、身份、预算、验收和恢复之间的技术关联。未经检索与实验，不声称具备新颖性、创造性或已取得技术效果。
