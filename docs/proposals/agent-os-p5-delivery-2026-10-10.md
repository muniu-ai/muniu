# P5 接入、导出与团队协作

本阶段基于 P4 `a958e5f`，在 `codex/agent-os-p5-delivery` 实施[已批准计划](agent-os-delivery-2026-10-10.md)的 P5。当前为实施记录，验证结果另行记录。

## 实施范围

MCP 先接入通过固定 HTTPS 端点暴露的只读资源。连接授权包含工作区、范围、有效期与读取限额；发现和导入均经过 Host。远程读取先保存请求、授权及持久 Job，再由带租约与 fencing token 的 Worker 执行。结果保存为受保护的资料快照，连接停用或授权版本变化阻止继续读取与传播。远程权限变化无法离线即时获知，界面明确区分导入快照与远程实时状态。

成果导出固定目标、计划、成果集合、条目及摘要，支持 DOCX、PDF 和 XLSX。文件保留来源及验收状态，不改变经营事实。PDF 使用固定许可与摘要的离线字体；DOCX 不含宏或外部关系，XLSX 将模型内容保存为文本。生成和保存均设置大小与执行时限。

导出与 MCP 导入共用派生 Asset 端口。附件先在事务外加密准备，最终 Kernel 事务重新检查权限并原子提交 Asset、密钥、来源及操作结果。所有元信息、下载、提取和模型读取均复验来源；导出还需重新核对原成果的权威凭据，不能通过复制文件绕过 Coding Gate 或原内容密钥撤回。

小团队责任记录使用独立版本与幂等命令，不修改目标执行者身份、计划授权或验收权限。首版责任人限当前可访问任务的工作区所有者或操作员；成员被移除后显示失效状态。分配、交付及阻塞通知在本地保存并直达任务，标记已读不等于审批或成果接收。不自动发送外部消息。

## 复用与边界

已审查旧 MCP 候选 `d13b4787c6f6105d0edecf79807ff648a9cf4740`，其旧协议依赖、布尔授权及网络边界不满足当前要求，不整体合并。沿用 P4 的 Host、KernelEventV1、受保护事件与 Asset，不增加第二套工作流数据库。

MCP 使用官方 2026-07-28 协议，只实现资源发现与读取，不执行远程工具、采样请求或远程返回的授权网址。首版不加入 stdio 连接。所有公共变更保持 `/v2`、`Idempotency-Key` 与聚合版本校验。

## 验证范围

- MCP JSON/SSE、分页、多内容、协议与消息校验、限额、SSRF、撤权、竞争派发及恢复。
- 派生 Asset 原子提交、来源闭包、跨工作区、循环引用、解密期间撤权及再入模型。
- DOCX/PDF/XLSX 独立内容读取、中文实际渲染、公式注入、字体许可与打包、限额和原成果失效。
- 责任分配并发、成员撤回、事件重建、通知去重和已读版本；分配不得转移执行授权。
- Desktop、CLI、Native 保存、窄窗口及原任务流程回归；完整工程基线和真实目标部署分别记录，不用静态检查代替部署验收。
