# P3 桌面与 CLI 实现记录

本记录覆盖经营候选、逐项验收、有限返工及经营事实衔接。以下记录界面行为和专项验证，完整工程检查与环境限制见[P3 验证记录](../verification/agent-os-p3-2026-10-10.md)。

## 已接入行为

- 经营与研究任务可声明多个交付项，每项有固定标识、名称与验收条件。研发任务仍只有一个完整代码候选，包含差异、Gate 结果与交付说明。
- 任务资料支持显式选择客户、服务、报价、订单、交付和复盘。选择服务时固定当前服务版本；选择已有报价时保留其服务版本。仅选中的来源引用进入目标，资料正文不复制到目标描述。
- 成果可逐项接收、暂缓或要求修改。接受前复核全部标准；要求修改只提交失败标准与说明。未提交项保留原决定。
- 独立复核未通过且费用已结算时，可在成果页要求修改或暂缓，不能接收未通过检查的成果。格式错误明确提示没有可验收成果；费用或外部结果待核对时禁用返工。最终接收后保留历史记录，新的交付要求另建任务。
- 返工先请求 Host 预览，展示受影响步骤、沿用工作、剩余额度、原期限和授权变化，再确认新计划。单执行者返工使用 `single-v2`，界面继续显示“单 Agent”。历史成果、决定与费用单独保留。
- 成果中 Host 派生的经营建议提供审阅入口。创建候选只发送固定成果身份和建议标识；采纳前显示字段差异、依据、影响及过期原因。采纳同时绑定候选版本、台账版本、候选摘要和预览摘要。
- 客户接受报价使用 `quote.confirm`，订单生效另用 `order.activate`。成果接收、客户验收与实际收款不互相推导。已接收成果可带版本依据进入交付草稿，由用户补齐真实交付信息再登记。
- Desktop 未知决定和返工请求保留原身份；候选未知请求跨面板重新打开仍复用原身份。CLI 新操作可显式使用 `--key`，不自动重发。
- 外部 CLI 的单执行者返工仍提供账单核对入口。费用未知时不允许继续返工；用量登记丢失响应后复用原请求。
- 历史业务资料通过版本与摘要回源，并提示当前事实是否已更新。候选撤权事件立即隐藏差异与采纳按钮；后续读取仍由 Host 检查权限。

## 专项验证

新增 `verify:agent-os-p3-ui` 包含客户端请求 1 项、静态决定与预览 4 项、单浏览器流程 14 项。19 项均通过，覆盖多交付项与未知创建请求、客户接受与订单生效分离、逐项决定丢失响应、部分决定汇总、返工预览后确认、事件刷新后的预览核验、候选请求跨面板恢复、撤权移除内容、交付草稿、来源定位，以及复核失败、格式错误、外部 CLI 账单核对、费用未知和最终接收后的操作限制。

已有专项结果：CLI 51 项通过；P2 团队静态 5 项与浏览器 9 项通过；P1 来源撤权 3 项通过；Desktop 与 CLI 类型检查及 Desktop Vite 构建通过。构建仍报告既有单包大小提示。

受影响的既有真实 Host 界面门禁已串行通过：`verify:business-ui`、`verify:goals-ui`、`verify:tasks-ui`，共 3 个完整门禁。经营门禁验证客户接受与订单生效分离，并继续完成交付、客户验收、收款和复盘；目标门禁验证整套接收及来源失效后的迟到响应保护；任务门禁验证资料引用、草稿与未知请求身份、成果接收。每个门禁还执行公共设置、插件、窄窗口和键盘检查；脚本未独立统计子场景数。

经营门禁首次执行在公共插件场景点击按钮时出现 DOM 脱离超时，当时另有工作区产物构建。保留失败日志后，在构建结束、产物稳定的条件下按相同断言重新验证通过；未据此修改生产行为或放宽测试。成功日志分别为 `/tmp/muniu-p3-business-ui-retest.log`、`/tmp/muniu-p3-goals-ui-final.log`、`/tmp/muniu-p3-tasks-ui-final.log`，首次失败日志为 `/tmp/muniu-p3-business-ui-final.log`。

真实 Host 流程脚本 `apps/desktop-mac/scripts/verify-delivery-ui.mjs` 已通过，使用真实 Host、Worker 与本地模型替身，覆盖多成果部分接收与返工、历史保留、客户及服务资料选择、候选采纳与业务事实分离、历史来源读取。首次执行发现预览保存后的事件刷新会清空确认入口，已补回归修复；之后修正脚本对自动返工和验收状态定位的假设。采纳后旧会话读取曾返回资料版本错误，Host 修复历史读取后再次完整验证，目标、成果和原会话均可读取，浏览器后台请求无异常状态码。

完整测试、Rust、企业环境与发布质量门由阶段主任务统一记录。本地模型替身不代表真实模型质量或费用改善，此文档不将未执行项视为通过。
