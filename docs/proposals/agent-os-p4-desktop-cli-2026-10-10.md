# P4 Desktop 与 CLI 接入记录

本记录对应[团队技能、记忆与受控跟进](agent-os-p4-reuse-2026-10-10.md)。页面与命令行均调用 Host `/v2` 契约；本文不代表真实模型评测或发布质量门已经通过。

## 已接入的操作

- Agents 页提供团队技能搜索、固定版本详情及权限说明。从最终验收的团队成果创建不可变版本；单 Agent 成果不冒充团队技能。
- 试用创建新目标，固定技能 ID、版本和摘要，保留全部交付标准。用户重新选择资料、模型与预算；不复制原任务的资料授权。普通任务仍默认单 Agent。待审阅计划只展示 Host 推荐且已评测可用的技能，用户点击采用后才生成新计划修订。
- 评测先登记固定配置，再上传受保护 JSON 报告并提交人工或确定性证据。报告复用资料读取入口，每次读取复验权限。启用、回滚、停用均使用 Host 的允许操作与启用记录版本；测试替身报告不能开启自动推荐。来源撤权后，目录只显示安全占位和 Host 提供的停用控制，首次打开也可停用。
- 记忆展示事实或偏好、用户或模型来源及版本。候选通过人工确认后才可采用；失效来源隐藏正文。记忆列表独立订阅工作区事件，旧响应不能恢复撤权内容。
- 主动跟进只允许已批准且未关闭的只读内置单 Agent 经营目标，使用原目标的模型连接。待核对或正在取消的目标不可新增跟进。界面要求明确勾选启用，并独立填写单次、周期及累计额度和有效期。未知费用继续标为待核对。
- 未知变更响应保留原请求身份、版本和输入，跨面板切换可继续核对。跟进通知直接定位关联目标。

## 验证入口

`npm run test:reuse-views` 验证静态内容与请求契约；`npm run test:reuse-cli` 验证 CLI 请求；`npm run verify:agent-os-p4-ui` 串行运行交互及真实 Host 场景。真实 Host 使用合成资料和可观察的模型替身，不计入实测质量收益。

当前验证：静态视图与 API 请求 14 项通过，CLI 全部 57 项通过（其中 P4 新增 6 项），交互替身测试 6 项通过；Desktop 类型检查通过。

真实 Host、Worker 与单浏览器的 7 个场景全部通过：已验收团队成果保存技能、固定技能版本试用并执行验收、受保护评测报告且测试替身被质量门阻止、用户偏好记忆确认、独立额度显式跟进、暂停继续与业务变化触发、Desktop 与 CLI 跟进状态一致。正常流程没有 HTTP 400 及以上的后台请求；960×640 窗口无横向溢出。成功日志为 `/tmp/muniu-p4-reuse-real-ui-fifth.log`。完整工程基线由阶段验收记录汇总。

首次集成过程中保留了四份失败日志，未降低状态或权限断言。两处测试定位需适配任务页按钮与报告条目，一处需区分记忆来源行和折叠说明。另一个失败揭示评测草稿在工作区事件刷新后丢失：现按工作区和固定技能摘要保留用户本地文件，受保护详情仍立即清理并重新检查权限。该缺陷先由独立交互回归复现，再通过修复和真实流程验证。
