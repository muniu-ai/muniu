# P4 技能、记忆与受控跟进

本阶段基于 P3 `2061ae5`，在 `codex/agent-os-p4-reuse` 实施[已批准计划](agent-os-delivery-2026-10-10.md)的 P4。当前为实现记录，不代表质量门已通过。

## 实施边界

团队技能从已验收的固定团队流程建立不可变版本。声明包含角色、输入输出、权限需求、检查规则和评测版本；新目标重新选择资料、模型和预算。技能内容不能授予权限，在途计划固定原版本。试用由用户显式选择，启用和回滚记录独立版本；真实评测未达发布门槛时，团队自动推荐保持关闭。

记忆保留现有提案、确认、范围及共享授权。新来源记录区分事实和偏好、用户输入和模型候选，模型候选的来源由 Host 从真实执行推导。候选确认后才进入关键词检索；每次实际采用的版本和来源写入受保护模型请求，调用前复验。经营事实仍以台账为准。

主动跟进由用户显式启用，绑定未关闭的原目标、选定业务对象、固定资料范围、执行者、有效期、停止条件及单次和周期额度。首批响应业务事实变化，采用内置单执行者进行只读分析；不自动采纳经营候选。每次触发创建独立目标和执行，使用持久触发身份与预算预留。没有相关变化时不调用模型，不生成重复通知。暂停不新增派发，关闭原目标、撤权或到期阻止后续工作。

跟进的周期额度独立于原目标额度。每次运行固定所属周期，未知费用保留占额，迟到费用归入原周期；暂停、重启和重试不重置次数或额度。用户仍通过既有成果验收入口决定结果。

## 必测范围

- 技能来源验收、版本摘要、模板与权限校验，失效来源、评测伪造、启停竞争和在途固定版本。
- 记忆确认前不采用、来源不可缩减、解密期间撤权、共享撤销、过期、跨工作区及实际请求清单一致。
- 跟进无变化、无关变化、重复触发、提交后崩溃、重启、暂停恢复、目标关闭和排队后撤权。
- 单次及周期预算、未知用量、迟到费用、累计次数与币种隔离。
- Desktop 与 CLI 使用同一公共契约，受影响页面和完整工程基线按仓库要求验证。

真实模型质量比较与真实企业部署需要单独证据。合成测试和实现评测入口不能证明验收率或费用已经改善。
