# 经营与研发统一任务入口

状态：按用户确认的统一入口实施。未发版，不增加兼容协议。

## 问题与范围

顶部“捕获”只保存机会或 Coding 任务，用户需要另找会话才能委派工作。经营工作被默认归入机会验证，输入框也缺少材料、约束和验收要求。

本计划复用现有 Goal、线程、执行预算和成果验收，提供“描述任务 → 审阅计划 → 开始执行 → 对话调整 → 逐项验收”的连续界面。经营任务创建独立经营助手会话；研发任务绑定已登记仓库。保留关联已有任务的入口。原有不可变 Spec、Gate、审批、隔离和资源版本检查继续生效。

## 交互

- 全局“委派任务”入口与 Command/Ctrl + J；任务页提供多行输入、经营与研发模板、约束、交付要求及真实可用模型。
- 支持添加 UTF-8 文本资料（TXT、Markdown、CSV、JSON），展示名称、内容和容量，允许移除。拒绝不支持的格式或超限内容，不承诺图片、PDF 或语音理解。
- 用户可以明确附加当前经营汇总快照，展示统计期间和版本。该资料只用于本次分析，不授予修改账目或外联权限。
- 审阅前不调用模型。模型、资料和额度进入已冻结计划；启动需明确确认。重试创建使用相同幂等键，不重复生成业务对象。
- 任务页同屏显示委派说明、执行状态、会话、权限及成果。执行中可补充消息或调整方向；结束后不隐式创建预算外执行。
- 验收逐条绑定成果版本；可下载成果。草稿只保留在当前窗口内，切换页面不丢失，不写入浏览器持久存储。

## 参考与取舍

参考 [ChatGPT 项目上下文](https://learn.chatgpt.com/docs/projects) 对持续工作资料的组织，以及 [长任务交互](https://learn.chatgpt.com/docs/long-running-work) 的目标、约束、验证和运行中补充指令。木牛的改进重点是经营与代码事实绑定、显式执行额度、同页跟进和内容验收；没有对“全面超越 ChatGPT”作未经测试的承诺。

这一入口先使用已有受预算约束的内置 Agent。外部 CLI 仍从研发任务详情调度，并沿用现有就绪检查；不把未接入的 WorkBuddy 显示为可用执行者。

## 验收与验证

新增 Host/Worker 回归测试：经营会话使用经营助手，模型请求包含原始目标，执行不会新增机会或修改经营事实；保留成果与预算约束。新增真实 Host 浏览器验证：统一入口、资料、草稿保留、幂等重试、经营计划与启动、研发仓库登记、完成后不可隐式新开执行、窄屏布局。保留既有目标验收与失效权限竞态测试。

提交前运行 npm test、npm run typecheck、npm run typecheck:desktop、npm run build:desktop、cargo test --locked、npm run verify:enterprise-fixture、npm audit --omit=dev、目标/任务/仓库/经营/研发 UI 门禁和 git diff --check。构建并安装通用架构桌面应用，运行 doctor；环境阻碍须如实记录。
