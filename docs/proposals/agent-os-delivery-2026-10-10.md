# Agent OS 经营到交付实施计划

状态：用户已批准 P0—P5，按阶段实施。日期：2026-10-10。起点：`464ff65`。P0—P4 已分别在专用工作树完成本地实现和验证；真实企业环境仍未通过本轮复验。P4 已接通技能、记忆和受控跟进，真实评测未通过前不启用团队自动推荐；P5 尚未实施。本计划补充[原多 Agent 提案](./agent-os-multi-agent-optimization-2026-10-09.md)，不把历史候选或研究结论当作现有能力。

目标是让客户需求、资料研究、方案报价候选、人工确认、研发或文档交付、成果验收与返工、客户验收和经营复盘形成连续流程。openJiuwen 作为交互与能力参考；保留现有 TypeScript、Rust、Host 和事件内核，不引入其代码依赖。

| P2：持久团队执行 | 私有编排模块、节点 Job、能力声明、原子预算与派发；研究、经营、代码交付三种固定模板 | 竞争派发、重启、撤权和取消验证通过；初期由用户显式选择团队 |

## P2 当前实施范围

- 新计划显式使用 `kind: "team-v1"` 和固定模板版本；旧单执行者计划的结构、摘要和重放语义保持不变。团队默认关闭，用户先选择模板，再审阅计划并授权。
- `packages/task-orchestration` 是 Host 使用的私有模块，保存通用预算与验收规则、模板、依赖校验和节点就绪判断。Kernel 提供中立协调事务端口，Worker 执行独立节点 Job；没有第二套工作流数据库。
- 研究模板包含两个取证节点、汇总、独立复核和汇合。经营模板包含需求、方案候选、复核、人工事实确认和汇合；确认节点不登记成交、客户验收或收款。
- 代码模板将现有规格、实现、Gate、人工批准候选保留在一个 Coding 节点内，再由只读 OPC 节点复核成果与证据。须同时启用 Coding 与 OPC，并通过真实沙箱能力检查；复核不得改写代码或绕过原治理。
- 首版节点固定一个内置模型连接，按同币种预算分配，共用累计期限。能力声明固定执行者、输入输出、工具、隔离、数据去向及未评测标识；当前不接受任意外部 CLI 进入团队。
- 首版不提供自主重规划、成果沿用或返工接口，仍提交一个完整交付项。模型复核仅提供辅助判断，程序证据和人工逐项接收仍为必要条件。

以上是本轮实现范围，不是验收通过声明。Desktop 的目标、计划、进展、成果视图以及 CLI 的团队入口共用 Host 契约；节点查询及完整流程的最终结果以验证记录为准。

## 必须保留的边界

- Host 是唯一组合根。新增私有 `packages/task-orchestration` 由 Host 装配；产品插件只依赖获准的 Contracts 和 SDK。先迁出通用 Goal 编排规则，再扩展节点，不实施微服务化或数据库拆分。
- `KernelEventV1` 及其受保护事实仍为事实来源。节点尝试、Execution、Job、预算预留与 outbox 经 Kernel 事务端口原子提交；节点完成和后继唤醒同样原子化。稳定去重键包含计划修订、节点和尝试。
- 计划固定输入、验收、执行者及能力版本。新修订废止旧版未派发节点；迟到结果留在历史。沿用成果必须显式核验输入、验收条件与当前授权。
- 子任务权限取父授权与角色能力的交集，每次外部工作前重新核验。模型上下文与工具承诺先持久化；未知副作用进入人工核对，不能借新尝试、Agent 或计划重放。必需沙箱不得降级。
- 首版固定依赖图，不允许模型自主增删节点。每目标默认并行 3、委派深度 1、累计节点 12、累计尝试 24；工作区更严格限制优先。P3 的用户返工设计最多自动推进两轮，累计额度、期限及 Coding 修复上限不重置；P2 只保留限额声明，不开放返工。
- 业务变更先呈现字段差异、来源版本与影响，人工采纳后通过领域命令应用。报价草稿采纳、客户接受、订单生效、成果接收、客户验收和收款互不推导。OPC 台账保持 CNY；执行费用按原币种核对，不默认换汇，未知费用不计零。
- 资料、索引、摘要和候选记忆继承来源保护约束。首版使用授权范围内关键词检索，不增加向量数据库。宏、脚本和文档外部链接不执行。
- 新公共接口使用 `/v2`、`Idempotency-Key`，更新聚合还需 `expectedStreamVersion`。新团队计划显式版本化，保留现有 0.2 单执行者语义；不引入早期状态加载器或迁移。

Desktop 与 CLI 共用 Host 行为；视图只改变呈现。保持当前工具链、私有 workspace、Coding 不可变 Spec/Governance/Harness/Gate/Evidence、中央工具策略和遥测默认关闭。

## 验收方法

每阶段遵循 TDD：先复现失败，再做最小行为修改，执行受影响测试和 UI 门禁。合并前执行仓库完整基线：`npm test`、两类类型检查、Desktop 构建、Rust `cargo test --locked`、企业 fixture、生产依赖审计和 `git diff --check`；契约改动同步生成与一致性检查。企业路径使用真实 PostgreSQL、S3、Vault 和沙箱恢复验证，缺环境明确记录。

交付评测冻结 60 个合成任务：经营、研究、研发各 20；开发集 40、留出集 20。双方固定模型版本、资料、权限和预算。安全恢复全部通过、留出集首次验收率不低于基线，且每个已验收成果的可比费用或人工时间至少降低 20%，才达到拟采用的质量门槛。未知费用单列，失败与返工消耗计入；留出集不得用于调参。

比较器只验证报告规则与证据格式，发布还需核对实际证据。当前没有真实模型基线、团队成绩或 20% 改善证据。策略依次经过离线评测、仅比较推荐的观察、按工作区有限启用；回滚只停止新派发，在途任务继续使用固定版本。
