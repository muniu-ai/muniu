# 客户到订单的业务链

E2.1 提供内置模式下的客户、联系人、商机、服务版本、报价、客户接受、合同和订单规则及查询。项目、交付、付款期与收支见[E2.2 业务说明](enterprise-fulfillment.md)；Sales 提供方属于 E5，当前接口拒绝在 Sales 模式中写入这些本地权威对象。

## 身份与使用前提

使用[企业登录入口](enterprise-identity.md)建立会话，由管理员按照[权限规则](enterprise-access.md)授予业务角色、对象范围和字段许可。管理员身份不自动获得业务读取或批准权。销售人员需要获准的服务版本读取权限和价格字段许可，才能据此准备报价；客户范围授权不会自动扩大到全部服务目录。

所有业务写入都要求同源、CSRF token 和 `Idempotency-Key`，更新已有对象还要求 `expectedStreamVersion`。浏览器、后续 Desktop 和 CLI 使用同一 Host 契约。当前交付的是业务 API，经营页面由 E6 实施。

## 事实顺序

| 步骤 | 约束与结果 |
| --- | --- |
| 建立客户、联系人、商机 | 对象独立版本，所有者由服务端当前主体确定；关联引用固定 ID、版本和摘要 |
| 发布服务版本 | 获准销售经理维护价格、范围、验收条件及有效期；替代旧版本时同一事务使旧版本失效 |
| 准备报价 | 引用有效服务版本，固定范围、验收条件、数量、单价和总额；客户、商机或价格来源过期时拒绝批准 |
| 批准报价 | 当前有资格人员能够读取关键字段，且与制单人不同；记录独立业务批准事实 |
| 登记客户接受 | 已批准报价尚在有效期内，引用已登记、未撤回且对应当前报价版本的证据；内部批准不能代替客户接受 |
| 建立并激活合同 | 依据已接受报价起草，再由另一有资格人员核对签署证据并确认生效 |
| 建立并激活订单 | 依据有效合同起草，由另一有资格且能读取价格等关键字段的人员批准；生效时在同一事务重新计算已生效订单的数量与金额，禁止超出合同额度 |

一个合同可对应多个订单。草稿订单不占用合同已生效额度；并发批准两个相互超额的订单时，只有一个可提交，另一笔完整回滚。合同版本不会因创建或激活关联订单而无故增加。

金额使用人民币整数分，服务单价与数量为正整数，乘法和累计计算使用整数运算并检查安全范围。当前未提供税额、折扣或跨币种换算。无价格字段许可时仍可读取获准对象的 `scopeLines`，其中只有服务、数量、范围与验收条件，不包含单价、成本或总额。服务价格、范围和验收条件复制进报价与订单的不可变条款；后续状态变化不改写已确认条款。

## 证据与批准

证据登记保存人员核对原始材料后的说明、对应业务对象版本、登记人、时间及字段类别。说明进入加密事实，客户端只获得受保护引用。程序校验身份、权限、范围、版本和引用完整性；不自动鉴定客户签字或纸质材料真伪。

证据继承业务对象的字段保护，并可增加保护类别。批准人不能借证据接口绕过价格、成本或联系方式权限。撤回证据立即阻止后续使用旧引用确认业务事实；已发生的业务事实保留，不因材料撤回而回滚。

业务批准、客户接受、签署确认和订单生效分别记录。Agent 可以在授权内准备候选，不能以 Agent 身份确认这些正式事实；制单责任仍记在负责人员名下。对外发包或写入外部系统还需 E3/E5 的执行准入，本包不会发送报价或修改外部系统。

## HTTP 接口

以下路径均以 `/v2/workspaces/{workspaceId}` 开头，完整请求与响应由[企业 OpenAPI](reference/enterprise-openapi.yaml)定义，客户端由同一 schema 生成。

| 路径 | 方法与行为 |
| --- | --- |
| `/business/commands` | POST 提交领域命令，最大正文 256KiB |
| `/business/{objectType}` | GET 列出当前有权读取的对象并过滤字段 |
| `/business/{objectType}/{objectId}` | GET 读取当前版本 |
| `/business/{objectType}/{objectId}/versions/{streamVersion}` | GET 读取历史版本，同时按当前权限过滤 |
| `/business-approvals/{approvalId}` | GET 读取有权查看的独立业务批准记录 |
| `/business-evidence` | POST 登记人员核对说明 |
| `/business-evidence/{evidenceId}` | GET 读取仍有效且当前有权读取的证据 |
| `/business-evidence/{evidenceId}/withdrawals` | POST 按当前版本撤回证据 |

重复请求返回原提交结果，同时重新检查当前权限；不能用同一个幂等键替换参数。版本冲突返回 409，应重新读取当前对象并人工确认是否重新提交，不自动覆盖。未知对象或不可用版本不返回伪造的空对象。

## 存储与模块边界

私有 `@mn/plugin-business` 固定为 0.2.0，只依赖 contracts 与 plugin-sdk；Host 装配权限、加密事务和 HTTP。它是随 Host 发布的受信业务模块，与进程权限等价，不是沙箱。可安装提供方及其五端口注册由 E5 实施。

业务事实写入 `KernelEventV1` 对应的加密领域记录，各聚合使用独立事件流。投影和缓存不能替代事实。公开版本摘要包含保留在加密事实中的随机盐，避免通过枚举价格或联系方式猜测隐藏字段。提交前检查会在加密准备后重新执行，拒绝等待期间失效的授权或期限。

## 验收

执行 `npm run verify:business-domain` 检查本包领域规则、持久权限与 HTTP 完整链。命令同时覆盖 E2.2 的交付与资金断言；各包的实际结果分别保留。冻结验收基线的 B01/B02 全链、双模式和真实业务试点仍由后续工作包验收。
