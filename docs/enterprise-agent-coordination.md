# 企业工作、动态计划与监督

E4.2 将已授权工作接入现有 Kernel、Job、Worker 和预算账户。工作范围、计划版本、节点尝试及结果分别持久保存，不使用固定团队模板限制节点数量。默认能力为经营分析、独立复核和成果整理；业务提供方动作由 E3/E5 的执行准入与提供方协议接入，未注册能力不能用于计划。

## 工作授权

人员先创建工作范围，再确认服务端返回的 `scopeDigest`。范围包含目标说明、明确对象与字段、验收条件、允许能力、模型绑定、预算和截止时间。创建草稿不产生模型调用；缺少模型、价格或有效额度时不能授权执行。

授权绑定不可变输入及实际模型配置。模型只能在当前工作允许的、仍可用的绑定中选择；停用一个模型不扩大允许清单，也不阻止使用另一个原本允许且未改变的模型。新模型配置不能静默替换在途节点的配置。

改变范围、目标、预算或截止时间需要修订范围并重新确认摘要。修订保留全部历史计划、结果和费用，归档旧授权下的完成节点。运行中尝试须先结束；未知结果须先核对。预算修订需要当前账户版本，不改变已用金额和已有预留，也不能低于两者之和或超过父账户上限。

## 计划与节点

计划可以由人员提交，也可以由获准模型提出。模型规划先预留工作预算，再读取任务摘要、允许能力、模型与来源索引；不会默认读取整个企业的数据。模型返回的来源别名由服务端解析为固定对象版本。

同一确定性校验器检查依赖环、重复节点、能力版本、模型、对象范围、期限、验收目标及累计预算。范围扩大仅保存为待授权建议，不创建新执行。首次模型规划和后续自动重规划都只能在原授权内新增只读分析或草稿节点，不能新增业务写入。

已开始、已完成及待核对节点保持原定义和执行标识。相同业务写入不能通过改节点名称再次安排。未开始节点可以调整；替换时旧 Job、租约和未用预算在同一事务失效，再创建新任务。旧 Worker 即使曾领取任务，也不能提交结果。

计划和就绪 Job 同事务保存。节点没有自行创建子 Worker 的接口；拆解请求只保存为建议，由同一协调服务再次规划和校验。自动重规划次数在请求入队时累计，取消或无效输出不会清零次数。节点数、尝试数及费用同时累计，不能用新计划领取第二份完整预算。

## 费用、等待和停止

入站评估接单后，只把原计量引用关联工作，不再次扣费。工作可用额度扣除已发生的入站评估；观察模式不自动创建工作。持续规则只有包含负责人已接受的工作范围和预算，才能在执行模式自动接单。

已接单主题的后续事件进入原工作订阅，不重复创建评估和工作。关闭规则阻止新接单；已有工作仍按自己的授权处理更新，订阅继续检查当前权限。订阅不授予额外资料权限。

节点请求、模型用量、受保护结果、后续任务与终结回执使用现有持久执行机制。已知费用必须结算；后续额度不足不会回滚前一节点已发生的费用，而是进入等待。等待不占用 Worker，额度释放后可以继续。

费用或外部效果未知时，原操作和预算保留待核对，不重新发送请求。其他节点失败不能覆盖工作的待核对状态。已知无业务副作用的只读失败可以在新计划中重试，历史费用继续计入预算。

暂停会取消未开始的 Job 并释放其预留；已开始的只读调用可能返回，按实际用量结算。恢复仍检查当前授权，再派发未开始节点。取消保存停止意图并尽力中断，未知结果不能显示为已取消。失去资料权限的原责任人仍可读取最小控制状态和取消自己的工作，响应不含原范围或内容。

## 监督与结果

监督先检查持久进展、租约、人员批准、回执与结果。心跳续租不能充当成果进展。执行节点连续十五分钟没有持久进展时，最多产生一次预算内只读诊断；输入仅含进展摘要，不能调用工具、修改计划、补偿或重放操作。节点已经恢复进展时，过时诊断停止。

诊断只提出继续等待、请求重新规划或请人员核查的建议，不直接执行建议。规划、诊断、分析和复核都计入工作预算。

节点输出是带来源及验收检查的结构化候选。服务检查格式、来源引用和验收项，确认工作范围摘要只授权该工作使用约定资料、能力和预算，不能替代业务批准或逐次执行批准。正式业务事实仍由 E2 的有资格人员确认；业务动作的精确执行批准由[E3 执行准入](enterprise-execution-admission.md)处理，提供方执行实现由 E5 接入。模型判断不能代替这些批准。当前结果需要按权限读取；成果验收、受保护知识和五套流程由 E4.3 衔接。

## HTTP 接口与入口

请求、响应和客户端来自[企业 OpenAPI](reference/enterprise-openapi.yaml)。写入要求企业会话、CSRF 和 `Idempotency-Key`；已有工作变更还要求 `expectedStreamVersion`，授权要求匹配范围摘要。

| 路径 | 行为 |
| --- | --- |
| `/v2/workspaces/{workspaceId}/goal-configuration` | GET 可见能力与模型配置，不返回凭据引用 |
| `/v2/workspaces/{workspaceId}/goals` | GET 最近可见工作；POST 创建待授权范围 |
| `/v2/workspaces/{workspaceId}/goal-adoptions` | POST 把已完成入站评估关联为工作草稿 |
| `/v2/goals/{goalId}` | GET 按当前权限读取工作 |
| `/v2/goals/{goalId}/control-state` | GET 原责任人可见的最小控制状态 |
| `/v2/goals/{goalId}/scope-revisions` | POST 修订范围，等待新的摘要确认 |
| `/v2/goals/{goalId}/authorizations` | POST 确认当前范围摘要 |
| `/v2/goals/{goalId}/plans` | POST 提交明确的任务图 |
| `/v2/goals/{goalId}/plan-proposals` | POST 请求一次预算内模型规划 |
| `/v2/goals/{goalId}/commands` | POST 暂停、恢复或取消 |
| `/v2/goals/{goalId}/reports/{attemptId}` | GET 按原来源权限读取节点候选 |

同一工作区可以配置多个不同的模型绑定，入站评估使用配置中的首个绑定。工作授权列出允许绑定；新工作实际使用的模型版本会固定保存。列表每次最多返回最近 100 项，更多记录以 `hasMore` 明示，完整历史翻页留待后续界面工作包。

`dev:enterprise` 的低频后台循环会推进已授权工作、处理计划及额度等待，并执行监督。程序化入口可通过 `runOperatingCycle()` 控制执行时机。它使用同一 Host 与 Worker，不增加另一套执行引擎。

## 验证边界

`npm run verify:agent-coordination` 执行计划、预算、企业权限、HTTP 和受影响 Host 检查。`npm run verify:agent-coordination-postgres` 使用隔离 PostgreSQL、合成 HTTP 模型及真实子进程，验证双 Worker、旧租约、撤权、进程终止、费用保留与恢复，同时复验 E3/E4.1。

本地工程记录见[E4.2 验收记录](verification/enterprise-e4-2-2026-11-05.md)。真实模型质量、Kind 全平台、容量和试点不由合成检查替代。
