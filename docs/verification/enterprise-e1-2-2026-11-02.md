# 企业经营平台 E1.2 验证记录

日期：2026-11-02。基线为 E1.1 提交 `ab30ef9`，分支为 `codex/enterprise-e1-2`。当前状态：E1.2 本地工程出口通过，真实 PostgreSQL 聚焦验收通过。完整 Node 套件分段执行，初轮失败与逐项复验结果如下；未宣称所有检查首轮通过。

## 变化与覆盖

新增对象范围、角色操作及字段权限的联合判断，部门、角色授予、对象共享、撤销、职责分离和额度配置。管理员不自动取得业务资格；批准人不能批准自己制单的事项，且必须读取领域命令规定的关键审批字段。权限描述由可信领域服务提供。

新增八个 `/v2` 操作，继续使用统一 schema 生成请求、响应、客户端与 OpenAPI。权限及额度事实使用加密事件和独立聚合版本；并发撤销只允许当前版本提交。

平台额度由受信运维端开通，工作区管理员分配不能突破平台上限。无额度、过期和单次入站评估超限均拒绝。额度政策检查与执行预算预留分开，E3.2 负责把两者接入同一准入流程。

PostgreSQL 新命名空间为 `mn_enterprise_v1`，S3 CAS 新根前缀为 `enterprise-v1/`。新参数不修改旧入口默认值，不提供旧状态读取或迁移。说明见[企业权限、额度与独立存储](../enterprise-access.md)。

本机为 8GB 内存。验证时同时存在其他应用容器，用户授权暂时停止 `muniu-industry-verification-control-plane` 并要求结束后恢复。测试脚本将 Worker 文件并发限定为 2；没有放宽任何授权、隔离、限额或计时断言。容器编译与本地回归分开执行，重试记录保留，环境相关失败不计作首轮通过。

要求与测试映射见 [E1 工程证据](../enterprise-acceptance/e1-evidence.md)。

## 待完成与依赖

尚未把权限接入 E2 全部业务查询、检索和导出，也未接入 E3.2 的执行准入、预算预留与异步撤权。当前纯权限断言不等于这些集成场景已通过。

托管入口、真实 S3/KMS、双 Host/Worker 联合恢复与容量仍按后续工作包验收。真实身份发行方、Sales、企业微信及试点环境由用户明确延后。已有通用容器验收使用临时 Go 镜像及资源限制，保留固定版本和校验，结果单独登记；不把旧入口的容器回归当作新企业入口验收。
