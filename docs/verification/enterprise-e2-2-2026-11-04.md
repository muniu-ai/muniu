2026-11-04。基线为 E2.1 出口 `57c9170`，分支 `codex/enterprise-e2-2`。E2.2 内置模式的工程与合成数据出口通过。E2.1、E2.2 均已完成本地验收；Sales 双模式、完整平台集成和试点仍由后续工作包验收。

## 交付范围

私有业务插件新增项目、里程碑、交付版本、客户验收、范围变更、付款期、到账、退款、冲销、减免、费用、指标版本、经营目标和固定复盘。规则在 Host 的加密事件事务中执行，各聚合保留独立版本。权限沿可信订单或项目关联检查；业务字段、来源和幂等重放均检查当前授权。

业务与接口说明见[项目、交付与资金](../enterprise-fulfillment.md)。本包交付内置模式 API，不包含 E6 页面、E5 Sales 接口或银行付款执行。

## 失败与修复

- 第一次完整回归有一项旧团队技能测试超出 30 秒等待窗口。业务节点已完成，汇总状态尚未被下一次查询读到；单独复验通过。测试等待期限改为其原有执行预算加结算窗口，业务预算与终态断言不变，随后完整回归通过。
- 当前余额校验起初未覆盖补录造成的历史日期超额。新增按业务日期逐点校验，付款期与订单金额保留生效版本，失败用例修复后通过。
- 复盘起初仅检查复盘对象本身，未在读取时重验来源；成本字段还可能在缺少价格许可时通过毛利暴露订单金额。新增来源重验和毛利所需价格许可检查，失败用例修复后通过。
- 范围缩减起初不能移除未交付里程碑，项目确认还要求提交所有里程碑。现在只修改明确列出的安排，移除空余里程碑，保留其他对象版本；总量和已接收数量仍在同一事务检查。两个失败用例及真实数据库复验通过。
- 早期验收启动因 Docker 或 Helm 不在指定搜索路径中止；修正验收环境后分别执行静态检查和限额部署回归。镜像准备还因直接使用本地镜像 ID，以及首次容器未覆盖继承的入口而中止；改用已核验本地标签及明确入口后通过。这些中止没有计为功能通过。

## 资源与边界

Node 堆限制 512MiB，单文件测试并发，低优先级执行。最终完整 Node 回归的进程树 RSS 采样峰值约 565MiB；RSS 包含堆外内存，不等于堆限制。部署回归容器合计采样峰值 578.01MiB，主机可用内存最低 24%，低于 18% 时会停止本次复验。最终 Linux 容器限制 512MiB、0.75 CPU，内部 Node 堆限制 256MiB；数据库单独运行，限制 192MiB、0.5 CPU。临时数据库使用独立名称、回环端口及内存和 CPU 上限，结束后删除本次资源。本次容器、网络和数据卷已清理。原有 11 个容器的标识、启动时间和运行状态在全部复验前后核对一致。验收镜像复用已核验依赖并校验当前运行文件摘要；本轮容器验证未重编 MinIO，也未在镜像内重新安装外部依赖。

真实 OIDC、Sales、企业微信、模型与试点环境仍未提供。Kind 全平台故障、容量和真实双模式验收属于 E5/E7/E8，不计为本包通过。没有迁移、修改或删除旧状态，没有部署生产环境。
