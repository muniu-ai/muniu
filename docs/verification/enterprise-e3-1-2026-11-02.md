# 企业经营平台 E3.1 验证记录

日期：2026-11-02。基线为 E0.2 提交 `8306de7`，分支为 `codex/enterprise-e3-1`。E3.1 与 E1.1/E1.2 独立实施。本地持久动作出口通过；Node 套件分段执行并复验失败项，容器、真实提供方和企业权限装配仍按后继包验收。

## 变化

新增分层预算账户、持久预留、承诺、未知费用保留与确定回执结算。新增提供方动作协调器及既有 Worker 的动作处理器，复用 Kernel 事务、Job、租约、outbox 与受保护日志，没有增加第二套工作流引擎。

精确批准检查补充工具调用、Execution、授权承诺、效果类别、期限和资源引用的绑定；执行与批准同时检查 Principal 当前状态。旧权限测试补齐真实 Principal 事实，不放宽授权规则。

接口、安全边界与尚未装配的产品能力见[持久动作与预算预留](../enterprise-actions.md)。

先执行失败测试，再实现预算所有者限制、精确批准、动作协议、配额约束、同步政策检查和核对时的物理 Job/投影一致性。未知动作检查确认外部调用只发生一次，原预算持续保留至核对后结算。

本机只有 8GB 内存。原默认 Worker 文件并发叠加容器编译导致真实进程测试超时，现将文件并发限定为 2，失败项单独执行。保留首轮失败与复验区别，不宣称一次 `npm test` 已全绿。未更改 Coding 的冻结契约、工具政策或必需隔离规则。

要求映射：预算账户与未知费用覆盖 P01 的执行原语；精确批准与当前主体检查覆盖 B03/A02 的局部断言；租约、取消、未知回执及数据库重开覆盖 R02/R03/R04。它们不代替 E4 动态任务或 E7 联合恢复的完整场景。

## 后继依赖

E3.2 需合入 E1.2，装配当前企业权限、业务批准、限定策略预授权和异步边界撤权。E4 的动态计划与就绪 Job 须在同一事务提交；本包提供事务内原语，尚未提供动态规划产品能力。E5 需提供实际业务提供方、可信回执和计量适配。真实外部环境按用户决定延后。

通用容器回归与新企业运行环境的集成验收分开记录。合成提供方故障测试不代替真实 Sales、企业微信或联合灾备通过。
