# OPC 经营管理 M1 验证记录

日期：2026-10-09。源码基线：`af69167`。实施范围见 [ADR 0014](../adr/0014-opc-business-management.md)，完整目标体系见[经营管理提案](../proposals/opc-business-management-2026-10-09.md)。

## 实现范围

服务和项目型一人公司的经营计划、客户及来源、产品版本、报价确认、已有合同订单、部分交付、客户验收、收款、退款、冲销、费用、金额调整和冻结复盘。每个工作区对应一个经营主体，使用 CNY 整数分与北京时间业务日。

OPC 主入口改为经营管理，机会验证保留为子流程。基础台账不依赖模型；Desktop、CLI 和 API 使用同一 Host 契约。经营 Agent、获客活动、伙伴管理、银行连接、库存、税票与多主体核算不在本轮实现范围内。

## 关键回归

- 历史合同可直接建单，期初已收不计入本期现金。1,000 元订单已收 400 元后，再收 300 元、退款 100 元，则应收 400 元；单独调减价款 100 元后，应收 300 元。
- 部分交付采用新增百分比，总量不得超过 100%。客户验收独立于交付和 Agent 成果；完整验收需要全部成果与客户确认依据。
- 报价固定客户及产品版本，修改报价通过新记录保留旧值；确认后不能重复生成订单。经营计划及客户、产品修订保留原版本。
- 过期版本、非法金额、无效引用、跨工作区/租户引用与模型身份写入被拒绝。撤权后用旧幂等键也不能读取旧回执。
- 真实 SQLite 存储中的经营内容及回执经保护，公开事件只包含工作区和命令类型。删除投影及幂等查询记录后可以重建，并重放原响应。
- 复盘按业务发生日和期间截止日计算；期初之前的未知余额拒绝计算。北京时间午夜不会把当天收款误判为未来。旧复盘不会被之后的事实改写。
- Desktop 在保存响应丢失、事件通知已推进台账版本时，重试仍沿用原版本和幂等键，不重复增加客户版本。收款冲销后的候选变化不妨碍重试；旧表单不能覆盖其他入口的新修改。日期查询失败后仍可修改日期恢复显示。
