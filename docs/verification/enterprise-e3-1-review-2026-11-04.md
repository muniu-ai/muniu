2026-11-04。在 `codex/enterprise-e3-1` 中合入 E2.2 出口 `2899d02`，保留原 E3.1 提交 `e66aae6`。E3.1 当前基线的工程与合成数据出口通过；本轮结果与初次记录分开保留。

## 实现与边界

E3.1 复用既有 Kernel 事务、预算账户、持久 Job、租约、outbox、受保护投影与 Worker。等待批准不占用 Job；提供方调用前先持久保存承诺；未知结果保留原操作和预算，不能重放外部写入。当前企业身份、对象和字段准入由 E3.2 装配，新企业入口的动作 HTTP 接口尚未开放。

真实 PostgreSQL 复验发现，同一操作换用新的请求键后，新增幂等记录缺少对应事件，受保护存储因此拒绝提交。现在记录独立 `action.prepare_resolved` 事件，用于重建请求键映射；不修改动作版本、重建 Job 或重复预留预算。已用 SQLite 失败测试确认问题，并经 SQLite 和 PostgreSQL 复验。

## 资源与后继

验证串行执行，Node 堆限制 512MiB；故障子进程限制 128MiB。数据库容器限制 192MiB、0.5 CPU，使用独立容器和数据库命名空间，结束后删除。部署回归的容器总内存采样峰值为 557.39MiB，系统空闲内存最低 26%。完整 Node 回归进程树 RSS 采样峰值为 626.5MiB；RSS 包含堆外内存，不等于 Node 堆限制。本次容器、网络和卷已清理，原有 11 个服务的容器标识、启动时间和运行状态核对一致。完整制品与日志摘要见[机器可读证据](enterprise-e3-1-evidence-2026-11-04.json)。
