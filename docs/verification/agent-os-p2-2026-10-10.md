# Agent OS P2 验证记录

日期：2026-10-10。分支：`codex/agent-os-p2-teams`，基于已包含 P0、P1 的 `c0ba245`。范围见[批准计划](../proposals/agent-os-delivery-2026-10-10.md)。本轮代码与本地验证已完成，保存在独立分支；没有合并主分支、发布或切换用户安装的应用。企业环境验证的限制见下表。

## 本轮范围

- `team-v1` 显式计划与三个固定模板：研究汇总、经营方案、代码交付。保留 0.2 单执行者计划结构、摘要、执行和幂等重放语义。
- Host 使用私有 `@mn/task-orchestration` 校验模板、依赖、能力、输入输出、权限交集及累计限额；旧 Goal 通用预算、用量和验收规则迁入该模块。
- Kernel 提供中立协调事务端口，原子提交节点尝试、Execution、Job、预算预留和 outbox；Worker 使用租约及 fencing token，终结与唤醒后继意图原子保存。
- Host 持久化团队调度意图，固定节点成果、来源和复核证据，提供启动、暂停、恢复、取消、人工决定和成果接收。Desktop 四视图与 CLI 调用相同 `/v2` 契约。
- 来源撤权后停止后续读取与外发，费用核对只读取计量记录。未知用量保留预留；未知副作用不能通过重试、另一 Agent 或新计划绕过。

当前没有自主重规划、成果沿用、多成果验收或有限返工。经营模板产出分析与方案候选，不提供字段差异采纳接口；人工事实确认不改变报价接受、订单生效、客户验收或收款记录。上述内容属于 P3。

## 实际边界

团队需要用户显式选择并审阅后启动；仅接入有同币种费用控制的内置模型。首版没有团队自动推荐、多模型选优、外部 CLI 团队成员或自动改变依赖图。每个团队目前提交一个完整交付项。

代码团队由一个 Coding 节点完成原有规格、实现、Gate、人工批准候选，随后使用只读 OPC 节点复核成果和证据。批准候选不会自动写回原仓库。必须启用两个插件并具有可信沙箱能力；缺少隔离条件时停止。模型自评及独立复核均不能替代权威程序证据和用户验收。

默认上限为并行执行节点 3、委派深度 1、累计节点 12、累计尝试 24；更严格的工作区限制优先。节点不能自主委派。暂停只停止继续派发，已派发工作可以继续至安全边界；暂停、恢复和人工等待共用原累计期限。成员本身中断、结果未知和费用待核对不自动创建新尝试。

本轮使用合成资料、模拟模型和确定性故障场景，没有调用真实模型评测。P0 的 60 项任务、留出集首次验收率及每项成果成本或人工时间改善门槛仍未测量，不得写为已降低 20%。企业真实 PostgreSQL、S3、Vault、沙箱恢复和目标安装环境分别需要本轮证据；本地测试不能代替生产部署验收。
