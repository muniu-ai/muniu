# Agent OS P3 验证记录

日期：2026-10-10。分支：`codex/agent-os-p3-delivery`，基于 P2 `e5928f2`。范围见[批准计划](../proposals/agent-os-delivery-2026-10-10.md)。本地源码与受影响界面验证完成，真实企业环境及安装包 Host 验证受阻；尚未合并主分支或切换已安装应用。

## 本轮范围

- 经营事实分别记录报价采纳、客户确认、订单生效、Agent 成果接收、客户验收和收款。经营候选从受保护成果及来源版本生成，由用户审阅字段差异后通过领域命令采纳；金额仍由 CNY 领域规则计算。
- 新计划支持结构化多成果和逐项接收、要求修改、暂缓。返工保存新修订与成果版本，原始成果、验收、费用和 Coding 证据保持可追溯。
- 旧单执行者在首次返工时使用显式 `single-v2` 计划，继续由原执行者完成。累计节点、尝试、费用、期限和 Coding 修复次数不重置；最多两轮用户发起的返工。
- 沿用成果需保存显式记录，并重新检查来源、原始成果和检查证据。旧成果保留原始身份；变更项单独生成和验收。
- 来源更新后仍可在当前权限下查阅历史业务版本，新执行和候选采纳必须通过当前版本检查。资料撤权后仅允许受限的费用核对，不能读取成果正文。
- Desktop 与 CLI 使用相同的决定、返工预览、确认及业务候选接口，公共路由均在 `/v2`，保留幂等键与聚合版本检查。

真实 Coding 验证首先发现：旧 `coding.execution` 来源具有专门的 Host 范围校验，但 Worker 上下文校验未识别该来源，导致返工节点未派发。修复后 Worker 按原 Execution 的范围、代际和摘要绑定，递归核对来源并拒绝循环；新增来源检查与相关上下文测试 7 项通过。第二轮返工预览还发现上一修订 Spec 被错误排除，已改为只排除当前计划自己的执行记录，完整流程复验通过。

本机该 Coding 流程最终用时约 63 秒。测试恢复检查间隔由 10 ms 改为 100 ms，单轮测试等待由 30 秒改为 60 秒；业务原有 120 秒期限、费用及 token 上限没有放宽，两轮返工期限相同。

## 边界

上述模型流程使用合成资料与模拟输出，未证明真实模型的首次验收率或成本改善。P0 冻结的 60 个任务尚未运行真实模型对照评测，不能宣称成本或人工时间已经降低 20%。团队自动推荐仍关闭。

Coding 每次交付一个完整代码候选，保持原有不可变规格、治理、Harness、Gate、证据和人工批准语义。候选批准不等于写回原仓库。后续技能版本、受控跟进、连接器扩展和成果导出分别属于 P4、P5，不能记为 P3 已完成。
