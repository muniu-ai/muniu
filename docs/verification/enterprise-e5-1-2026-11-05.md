## 实现与接口

内置提供方接入企业身份、对象与字段权限、独立业务聚合及原有持久 Job。五端口处理原始版本快照、增量游标、固定输入、三种受控动作和回执；业务效果与提供方成功回执原子保存。新增独立跟进任务，不建立另一套任务执行引擎。八项 Host 接口见[内置业务提供方](../enterprise-builtin-provider.md)。

[ADR 0016](../adr/0016-provider-preparation.md)将准备请求与正式动作分开。准备阶段不虚构执行授权或预算预留；报价仍须有效业务批准。正式执行核对实际动作、责任主体、精确执行批准及原 Job 租约。人工确定性动作使用零模型预算，不能借此申请模型额度或绕过批准。

共用套件包含 16 个必测场景。独立导出包包含权威 schema、声明、解析器、同一断言和仅依赖 Node 的完整性校验器。正式冻结要求来源工作树干净，记录来源提交与清单摘要。说明见[提供方契约套件](../enterprise-provider-contracts.md)。Sales 当前只登记固定对象归属，全部端口保持不可用，实际实现由 E5.2 完成。

## 发现与资源

并发重放原动作时，第二次读取可能在异步加载回执期间发生撤权。无新事件的事务分支不会执行写入检查，旧记录曾可返回成功回执。新增用例由第二仓库真实提交原动作和撤权，并确认进入该分支；现统一在返回回执前检查当前权限和动作摘要。测试确认业务仍只产生一个跟进任务、目标只推进一个版本。

最初数据库、完整类型、Rust 和组合部署检查曾因宿主空闲内存低于 18% 被主动中止，中止记录不计为通过。已减少临时启动脚本保留的 Node 进程，降低验收数据库内存参数，并为中断清理登记本次资源。所有构建、测试和容器门禁串行执行；不停止原有服务。

最终 PostgreSQL 测试进程树 RSS 采样峰值 161.2MiB、数据库容器 82.96MiB；Linux 容器采样峰值 86.42MiB。短时进程可能落在采样间隔之间，采样值不代表严格峰值或生产容量。组合部署两次均因资源保护中止，第二次已降低限额并错开四个应用实例的启动。两次清理退出码均为 0，原有 11 个服务的标识、启动时间和运行状态前后相同；这两轮不计为通过。随后移至独立 GitHub 执行器完成同一实际组合部署检查，未减少业务断言；执行器启动时报告总内存 15,983MiB，该值不代表测得的生产容量。

远端[运行 41953938972](https://github.com/muniu-ai/muniu/actions/runs/41953938972)的所有步骤均成功。共用套件 56 项、E3/E4/E5.1 PostgreSQL 故障断言、完整组合部署及清理均实际执行，最后确认生成源文件未改变。契约包来源为干净提交 `737b773`，清单 SHA-256 为 `95293c3d39823138e4ba284a70603893a78d682c013211c94fd49040df971885`，可由独立 Node 校验器验证后供 E5.2 使用。
