# E2.1 验收记录

2026-11-04。基线为 E1 出口提交 `d60c605`，分支为 `codex/enterprise-e2-1`。E2.1 的内置业务工程与合成数据出口通过；E2.2 尚未实施，E2 整体未完成。

## 交付与边界

新增私有业务插件的确定性规则、加密事件持久化、当前权限过滤和八个 `/v2` 操作。支持客户、联系人、商机、服务版本、报价、独立业务批准、客户接受、合同和订单。每个聚合独立版本；相关变更在一个事务提交，重复请求保留首次结果并重验当前权限。

业务 API 及适用范围见[客户到订单](../enterprise-sales-chain.md)。本包不包含业务页面、外部报价出包、Sales 权威对象写入、交付或资金记账。人员证据登记保存核对说明，不能代替程序鉴定签字真伪。

价格隐藏时，获准人员仍能读取 `scopeLines` 中的服务、数量、范围和验收条件。其字段采用明确白名单，不包含单价、成本和总额。

| 要求 | 本包证据 |

| A02 异步边界的业务提交部分 | 报价在异步加密期间到期时不写入批准事实；撤权后不能通过重复请求读回旧响应 |
| R04 事实恢复 | SQLite 重开和真实 PostgreSQL 重新创建服务后重放一致；数据库中不出现业务正文、价格字段和私有版本盐 |

## 失败与修复记录

- 缺少业务接口时 HTTP 用例返回 404，接入统一 schema 和 Host 后通过。
- 商机更换关联客户后未更新部门，可能沿用旧范围；同步部门并覆盖无部门情况后通过。
- 未批准报价只重验商机，未重验其客户引用；补充当前客户版本检查后通过。
- 已登记证据在业务对象推进版本后不能幂等重放；保留原引用，同时检查当前权限、原保护类别和撤回状态后通过。
- 批准记录查询只检查对象范围，未检查普通字段许可；补充字段检查后通过。
- 首轮容器回归在 PostgreSQL 重启时发现借出连接的 `error` 事件未处理，Host 因此退出。新增连接事件处理和脱敏记录，仍由 pg 拒绝失败查询并丢弃失效连接；不自动重试未知事务。定向检查及完整容器复验通过。
- 独立数据库测试曾在容器端口映射尚未公布时失败；补充有限等待与仅允许回环地址的检查，后续业务断言通过。
- 一次临时镜像制品准备因已有符号链接复写失败而中止；修复制品准备后重新构建，该次中止未计为功能通过。

## 资源与后续

本轮串行验证，Node 堆限制为 512MiB，使用低优先级进程。完整 Node 回归计时工具记录最大 RSS 约 519MiB；RSS 包括堆外内存，不等于堆限制，也不代表整机总用量。容器每 10 秒采样一次，采样峰值合计 559.32MiB，主机空闲内存最低 26%，未触发低于 18% 时停止复验的保护。

容器镜像复用已核验且未变化的外部 Linux 依赖，复制当前源码及编译结果并校验运行文件摘要。新增内容只有第一方业务 workspace 链接，没有更换外部依赖版本。完整容器回归镜像与最后范围展示修复后的专项镜像分别登记，不能将它们混称为一个提交镜像。详见[制品与资源证据](enterprise-e2-1-container-2026-11-04.json)。

测试资源均清理，原有 11 个服务的容器 ID、启动时间与运行状态核对一致。Kind、真实企业登录、Sales、企业微信、容量与试点仍属后续整体验收，不计为本轮通过。
