# 项目、交付与资金

E2.2 在内置模式下提供项目履约、资金登记和经营复盘 API。先按[客户到订单](enterprise-sales-chain.md)建立生效订单，再授予项目和财务人员对应订单范围及字段权限。界面由 E6 实施，Sales 连接由 E5 实施，当前不执行银行转账或外部付款。

## 项目与客户验收

一个生效订单对应一个项目。`project.create` 复制订单公开范围，`milestone.create` 按条目分配承诺数量，累计不得超出订单。条目保留服务、单位、范围和验收条件，项目人员不需要价格权限。

`delivery.report` 保存交付候选，`delivery.receive` 由人员记录内部接收；内部接收不产生客户验收。`acceptance.prepare` 从已接收交付准备客户验收候选，`acceptance.confirm` 由另一合格人员核对已登记证据后确认。确认人同时不得是交付制单人。数量分别按条目计算，不能将不同单位合并；客户累计验收不得超过交付，内部累计接收不得超过里程碑。

`GET /v2/workspaces/{workspaceId}/business-progress/{projectId}` 返回各条目的承诺、内部接收、客户验收和未完成数量。未完成数量等于承诺减去客户验收；交付六项、客户只验收四项的十项订单，仍有六项未完成。

## 范围变更

| 命令 | 资格与结果 |
| --- | --- |
| `change_request.prepare` | 项目人员提出变更说明，一个项目同时只保留一个未结束变更 |
| `change_request.price` | 具有订单写入及价格许可的销售人员准备新条款；可保留原条目编号调整数量，或引用有效服务版本新增条目 |
| `change_request.approve` | 合格销售经理读取关键金额并核对证据；不得是变更提出人或商业制单人；同一事务修订合同、订单并暂停项目新增交付 |
| `change_request.project_confirm` | 项目人员确认最新订单范围及受影响里程碑安排，之后恢复交付 |
| `change_request.cancel` | 取消尚未商业批准的变更；已批准变更须通过新的业务变更处理 |

合同新金额由“原合同金额 − 原订单金额 + 新订单金额”确定，其他订单和未分配合同数量保留。不能降低到已交付数量以下；项目确认时，每个里程碑也不得低于其已接收数量。付款期或资金分配与新订单金额冲突时，商业批准整体拒绝，不能先改订单再补救。商业批准前仍可按原范围交付，但项目或相关来源版本变化后须重新准备变更。商业批准后，交付申报、内部接收、客户验收准备和确认均暂停；项目确认后恢复。变更前保存的交付候选若引用已修订里程碑，须按新版本重新申报。确认请求只列出需要修改的里程碑，其他里程碑保持数量与版本；每次最多修改 100 个。尚未交付的里程碑可用空条目列表移除，有已接收数量的里程碑不能移除。所有保留及修订条目一起校验总量。旧订单、交付和商业批准可按原版本读取。

## 资金与成本

资金均使用人民币整数分。`payment_schedule.create`、`receipt.prepare`、`refund.prepare`、`adjustment.prepare` 和 `expense.prepare` 保存候选，各自的 `.confirm` 由另一名有资格的人员核对证据后确认。Agent 不能确认正式资金事实。未确认或已取消的候选不进入余额，已确认记录不允许直接修改或取消。

| 事实 | 计算口径 |
| --- | --- |
| 付款期 | 已确认付款期总额不得超过订单金额，每期保留金额和到期日 |
| 到账 | 分配到同一订单的已确认付款期；未分配部分单独显示，不自动冲抵付款期或其他订单 |
| 待分配现金归集 | `receipt_allocation` 单独批准后分配到同一订单付款期，不增加到账总额，不能超过尚未分配的净到账 |
| 实际退款 | 减少净到账，并明确释放原收款分配 |
| 错误入账冲销 | `adjustment.prepare` 的 `receipt_reversal`，与实际退款分别累计 |
| 减免 | `write_off` 减少对应付款期未收金额，不伪造到账或退款 |
| 付款期修订 | `schedule_revision` 固定新金额、到期日和业务日期；独立批准并保留旧条款，不能低于已分配与已减免之和 |
| 支出 | 归集一个项目，确认金额进入成本；不自动推断成本已经齐全 |

`GET /v2/workspaces/{workspaceId}/business-balances/{orderId}/{asOfDate}` 返回指定业务日期、以当前已登记事实重算的余额。净到账等于到账减实际退款和冲销；未收余额等于订单金额减已分配净到账和减免。待分配现金单列，因此不能把未收余额直接等同于订单金额减净到账。订单金额取商业批准日期当天及之后生效的版本，付款期金额和到期日取修订业务日期生效的版本；同日多次修订按提交顺序取最后一版。金额和付款期修订按业务日期校验，拒绝造成任一历史日期超额分配的补录。

`project.costs.confirm` 固定当前全部已确认费用引用；无费用时必须明确提交 `zeroCost: true`。新的费用、未确认费用或订单范围变化会使成本完整性失效。`GET /v2/workspaces/{workspaceId}/business-costs/{projectId}` 只有在成本完整时返回毛利，否则 `marginMinor` 为 `null`。这里的毛利采用订单口径，即有效订单金额减已确认项目成本；退款、冲销和减免分别进入资金指标，不直接改变该差额。它不表示按会计规则确认的收入或现金利润。支出与毛利使用成本字段许可，毛利还要求订单价格读取权。

业务日期使用 Asia/Shanghai；资金保存实际发生日期，事件保留系统登记时间。交付接收与验收日期取人员确认时间的业务日期。退款和冲销不得早于原到账日期。补录不会改变已经保存的复盘。

## 经营目标与复盘

独立指标版本需要管理员另行授予读取或维护范围，订单范围不会自动覆盖指标目录。`metric.publish` 由人员发布固定算法的指标版本，当前算法为 `business-balances-v1`，支持期间净到账、期末未收余额和期间已确认支出。`objective.create` 固定订单、指标版本、期间、目标值和当前负责人。算法不能由模型或客户端公式替换，调整目标需创建新对象，旧目标仍可引用。

`business_review.snapshot` 保存期间、系统观察时间、来源版本及计算结果。资金部分区分期内流量和期末余额；交付部分统计截至期末已确认数量；成本不完整时隐藏毛利。成本目标和结果放在成本字段内。迟到事实需要生成新的复盘，旧复盘不自动重算。

复盘通过通用业务对象接口读取。每次读取都重新检查复盘及相关来源的当前权限；失去来源权限后，不能借自有复盘读取历史金额、交付或成本。历史复盘代表生成时已知的事实及条款，重新按旧日期查询不等于还原当时尚未登记的事实。

## 接口与验证

上述写入均使用 `POST /v2/workspaces/{workspaceId}/business/commands`，要求 `Idempotency-Key`；已有对象更新要求 `expectedStreamVersion`。证据和历史版本接口沿用[客户到订单](enterprise-sales-chain.md#http-接口)。字段、命令及响应由[企业 OpenAPI](reference/enterprise-openapi.yaml)生成，未经授权的字段不会出现在查询结果中。

执行 `npm run verify:business-domain` 验证金额、交付、变更、成本、复盘、权限及 HTTP 链路；`npm run verify:business-postgres` 使用独立 PostgreSQL 容器验证持久事务、双服务并发及恢复。两项检查都包含实际断言。工程结果见[E2.2 验收记录](verification/enterprise-e2-2-2026-11-04.md)，真实 Sales 双模式、容量和试点由后续工作包验收。
